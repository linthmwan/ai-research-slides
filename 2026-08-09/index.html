把「人類替 agent 改 scaffold」改成 reset-free 的自我修補 loop：prompt、sub-agents、skills、memory 一邊互動一邊被 Refiner 更新。

Source: arXiv cover p.1; GitHub README line 34; Fig.1 p.2
TL;DR

不是讓模型「想久一點」，而是讓它在同一條長程軌跡裡，改造自己用來行動的 harness。

Continual Harness 把 trajectory 變成 prompt / sub-agent / skill / memory 的 CRUD edit；再把 open-source model 放進同一 live-refining loop 裡做 reset-free DAgger+PRM+soft SFT。

§4.2 p.6
Method · Harness state

Harness 不是單一 prompt，而是四個可編輯 store

H = (p, G, K, M)
  • p: system prompt / strategy guidance
  • G: specialized sub-agents
  • K: reusable skills, including executable tools
  • M: persistent memory / observations
Ht+1 = Ht ⊕ Δ
  • Δ=(Δp, ΔG, ΔK, ΔM)
  • CRUD operations over G/K/M; prompt replacement for p
  • same meta-tool API can be used by Agent and Refiner
§2.2 p.3-4; §3.1 p.4
Method · architecture

Two-loop architecture: agent acts, Refiner edits, no reset

Fig.2 p.4; §3.1 p.4; §3.3 p.5
Method · Refiner

Refiner 的工作不是反省一句，而是四輪 component repair

  1. Prompt pass: condition on recent failures and rewrite p.
  2. Sub-agent pass: create repeated-pattern agents, edit failing agents, delete unproductive ones.
  3. Skill pass: codify successful sequences; repair executable code that raised exceptions.
  4. Memory pass: add missing facts, update stale entries, demote areas already passed.
關鍵是 mid-episode：late-game failure 不需要等下一個 full reset 才能被學到。
§3.2 p.4-5
Mechanism crown

Reset-free 的價值在於：錯誤訊號不被 episode boundary 洗掉。

Failure signatures 在同一次長程互動中累積；早期 navigation loop、late-game battle、dialogue chain 都能成為後續 Refiner edits 的依據。

§4.5 p.8; Fig.7 p.8
Why the co-learning claim is stronger

它排除了「只是 early-game protocol artifact」的弱解釋

  • Beginning-of-game and mid-game checkpoint curves share the same qualitative shape.
  • Untrained Gemma-4 baseline shows zero advance beyond starting milestone.
  • Cross-family Qwen3.5 can produce parseable tool calls but cannot leave starting area without supervised warm-up.
  • Therefore the evidence points to training on own rollouts through a continually refining harness, not just static imitation.
§4.5 p.8; Appendix D.4 p.26-27
Limitations

這篇最重要的限制：loop 需要能力地板，也還仰賴 frontier teacher

  • Capability floor: Flash-Lite HCH underperforms minimalist baseline on Emerald.
  • Residual Hexpert gap: dialogue-heavy gym interiors and multi-turn battle strategy remain hard.
  • Teacher dependency: open-source co-learning uses Gemini relabeling; evaluated Gemma-4 models cannot serve as both teacher and trainee.
  • No convergence claim: sustained progress is reported, but saturation / convergence point is not established.
  • Reset-free vs reset head-to-head: left open under same task and budget.
§4.3 p.7; §6 p.10
Interpretation for agent builders

把 agent 改成「會改自己的工作台」，比單純加 memory 更接近長程 self-improvement。

但 scaffold synthesis 會放大模型的能力差：強模型能利用新增工具與 memory；弱模型只是多了一堆會誤用的狀態。

§4.4 p.7-8; §6 p.10
Engineering takeaway

如果要把這個概念搬到 coding / ops agents

  1. Refiner 要有明確 edit surface：prompt、sub-agents、skills、memory 各自 CRUD，不要只讓它追加 reflection。
  2. 用 sliding window 找 failure signatures；把 late failure 直接寫回 harness state。
  3. Bootstrap cache 要分 frozen vs updating 做 ablation，否則看不出 inheritance 與 continued refinement 的差別。
  4. 要設 capability floor gate：弱模型不一定適合開自我修改。
  5. 評估不要只看 task success；要像 Fig.8 一樣量 component-level repair 是否真的變好。

Appendix · exact quote

Mid-episode edit 的核心定義

“Every F steps, a Refiner reads the recent trajectory window for failure signatures and emits per-component edits Δ=(Δp, ΔG, ΔK, ΔM). The agent does not reset; the updated harness Ht+1 = Ht ⊕ Δ enters the agent’s context on the next step.”

每 F 步，Refiner 讀最近 trajectory window 找 failure signatures，對 prompt/sub-agents/skills/memory 產生 edits；agent 不 reset，更新後的 harness 立刻進入下一步 context。§3.1 p.4
