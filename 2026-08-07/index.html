PM-KVQ: Progressive Mixed-Precision KV Cache Quantization for Long-CoT LLMs

Tengxuan Liu, Shiyao Li, Jiayi Yang, Tianchen Zhao, Feng Zhou, Xiaohui Song, Guohao Dai, Shengen Yan, Huazhong Yang, Yu Wang
ICLR 2026 Conference PaperarXiv:2505.18610v2KV cache PTQ · long-CoT

A practical KV-cache compression method for reasoning models: spend memory early, spend more bits on sensitive blocks, and make short calibration see long RoPE phases.

Source: cover p.1; arXiv 2505.18610v2; OpenReview forum Vem6FQvRvq
TL;DR

PM-KVQ treats long-CoT cache compression as a memory scheduling problem, not only a quantizer choice.

It keeps early KV cache at higher precision, lowers bit-width only when the memory budget is full, allocates bits by layer sensitivity, and uses positional interpolation for cheaper long-context calibration.

Problem

Long-CoT turns KV cache into the deployment bottleneck.

  • Reasoning LLMs can generate up to 128K tokens with multiple rationales, so KV cache grows with the whole generated history.
  • The paper reports long-CoT KV cache memory overhead around 10GB-100GB, often comparable to or larger than weights.
  • Short-context KV quantization methods were mostly tuned for <8K tokens; long outputs expose error accumulation.
For long-CoT, memory is not a static capacity constraint; it changes token by token during decoding.
§1 p.1-2; Table 1 p.3
Failure modes

Two things break when short-context PTQ is copied into long-CoT.

1. Cumulative error
  • Directly quantizing K/V tensors at every decoding step introduces a new lossy error per generated token.
  • As output length grows, the errors compound and reasoning performance drops.
2. Calibration mismatch
  • RoPE rotates Key channels by position; low-frequency channels can need far more than 512/2K tokens to reveal their range.
  • Short calibration therefore underestimates outlier transfer factors for long-context Key cache.
§1 p.2 lines 69-80; §3.3 p.5-6
Core idea

Use all available memory before accepting low-bit damage.

  1. Progressive quantization: start at 16-bit, shrink 16->8->4->Fbit only when memory is full.
  2. Block-wise allocation: assign higher Fbit to more sensitive transformer blocks under the same global budget.
  3. Positional interpolation: make 2,048-token calibration approximate 8,192-token RoPE positions.

Progressive quantization

The cache starts high-precision and shrinks only when pressure appears.

  • For each block, Fbit is the final bit-width after all shrinking is done.
  • At generation start, KV cache is stored in 16-bit to reduce early accumulated error.
  • When memory fills, bit-width follows powers of two: 16 -> 8 -> 4 -> 2.
  • Short responses may never reach Fbit; long responses still benefit from more accurate early tokens.
schedule: KV16 -> KV8 -> KV4 -> KVFbit as memory fills
§3.1 p.4; Appendix C.8 p.18
Bit shrinking detail

Equivalent Right Shift preserves the dequantize-then-requantize behavior cheaply.

Xb = ((22b - 2b + 1)(X2b + 2b-1)) >> 3b
  • Keeps zero point fixed: Zb = Z2b.
  • Rescales dynamic range: Sb = (2b + 1)S2b.
  • Implemented with integer addition and shifting, not backpropagation.

Block-wise memory allocation

Uniform Fbit wastes the gap between “2-bit fits” and “4-bit OOM”.

  • PM-KVQ estimates per-block sensitivity to K/V perturbation with a first-order Taylor approximation.
  • Then it solves an integer program: one bit-width per layer, minimizing total sensitivity under memory budget M.
  • The optional set is B={4,8} for LLaMA-8B and B={2,4} for the other long-CoT models.
min Σi,b xi,bsi,b subject to Σi,b xi,bMem(Qb(Ki,Vi)) <= M

Calibration with positional interpolation

Short calibration fails because RoPE makes Key channels position-periodic.

  • QServe-style channel reparameterization learns λi from calibration samples.
  • But low-frequency RoPE channels can have very long periods; the paper reports 54,410 tokens for the lowest-frequency sine curve in Qwen-7B.
  • PM-KVQ scales RoPE positions by s during calibration, so 2,048 tokens with s=4 approximates 8,192-token coverage.
RoPE PI: cos(s·mθi), sin(s·mθi) -> effective length = s x calibration length
§3.3 p.5-6; §4.1.1 p.6
Pipeline

PM-KVQ separates offline planning from online cache updates.

Before inference
  1. Profile block sensitivity on calibration data.
  2. Solve integer program for Fbit per transformer block.
  3. Apply channel-wise reparameterization using PI calibration.
During inference
  1. Generate while storing new KV at high precision where possible.
  2. When the memory budget is saturated, shrink existing KV cache.
  3. Continue until each block reaches its allocated Fbit.

Result interpretation

The accuracy gain is mostly from not quantizing too early and not spending bits uniformly.

PM-KVQ can use the same final low-bit target as KIVI, yet produce higher-quality early states and stronger sensitive layers. That is why it can improve pass@1 while staying in the same memory budget.

Accuracy-throughput tradeoff

The paper accepts a small speed penalty against KIVI to buy much more accuracy.

  • PM-KVQ has 2.45-16.18% lower throughput than KIVI in the tested settings.
  • But the paper reports 10.57-23.48% relative accuracy improvement over KIVI.
  • The extra overhead mainly comes from higher bit-widths during parts of inference; bit-width shrinking itself is described as negligible.
This is the right trade for reasoning workloads: a small serving penalty can avoid a large pass@1 collapse.
§4.3 p.9 lines 887-935
Mechanism crown

PM-KVQ wins because it matches precision timing, layer sensitivity, and RoPE phase coverage to the long-CoT setting.

  • Timing: early tokens remain high precision before the budget saturates.
  • Sensitivity: later blocks and Qwen-7B block 0 are assigned more memory.
  • Calibration: s=4 positional interpolation gives the accuracy of longer calibration at lower cost.

Limitations

The method is strong but not universal yet.

  • The authors do not evaluate all attention mechanisms; they call out Multi-head Latent Attention (MLA) as different from GQA.
  • They do not combine PM-KVQ with other system-level optimization techniques or inference engines.
  • OpenReview reviewer JSON was unavailable in this run due to HTTP 403, so no reviewer-score claims are included.
Limitations p.20 lines 1978-1982; ingest log
Engineering takeaways

What to copy into a real inference stack.

  1. Do not pick one KV bit-width globally. Treat the budget as layer-wise and time-varying.
  2. Profile layer sensitivity. The figure evidence says later blocks may deserve more bits.
  3. Make calibration context-aware. For RoPE models, short calibration without PI can miss low-frequency Key channels.
  4. Measure prep latency separately. PM-KVQ’s runtime win is clear, but model refresh cadence determines whether 17-120 min setup matters.
