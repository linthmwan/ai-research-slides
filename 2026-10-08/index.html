FSA: efficient Native Sparse Attention kernels

Flip the kernel loop order, not the sparse-attention algorithm.

Ran Yan · Youhe Jiang · Zhuoming Chen · Haohui Mai · Beidi Chen · Binhang Yuan
HKUST · Carnegie Mellon University
ICLR 2026 PosterarXiv:2508.18224v3

Full paper title: FSA: An Alternative Efficient Implementation of Native Sparse Attention Kernel

Paper cover p.1 · ICLR 2026
TL;DR

FSA makes NSA fast for small GQA groups by batching query tokens per KV block instead of padding query heads.

It is a kernel implementation change: retain NSA sparsity, remove hardware-unfriendly padding.
3.5x1.25x1.36x
  • Kernel latency vs NSA: up to 3.5x lower.
  • End-to-end training vs NSA: up to 1.25x faster.
  • Inference prefill vs NSA: up to 1.36x faster.
Abstract p.1 · §4.2-4.3 pp.8-9
WHY THIS MATTERS

Sparse attention still loses if the kernel wastes tensor-core work

  • At 64K context, attention can account for 70-80% of decoding latency.
  • NSA reduces algorithmic work using compressed, selected, and sliding-window KV attention.
  • But irregular selected-token access and padded tile shapes can erase the theoretical FLOP advantage.
The paper targets the gap between sparse complexity and elapsed latency.
§1 pp.1-2 · §2.2 pp.3-4
HARDWARE ROOT CAUSE

Vanilla NSA batches heads; small GQA groups force padding

  • NSA outer loop: query token / grouped query heads.
  • When GQA has fewer than 8 Q heads, tensor-core tile requirements are not met.
  • The kernel pads heads, loads masked data, and computes discarded results.
GQA group size: g = h / hK

On Hopper, matrix tile dimensions need at least 8 for single-warp processing.
Padding is a hardware tax, not an algorithmic requirement.
§1 p.2 · §2.1 p.3
CONTRIBUTIONS

Four claims, one systems thesis

  1. Invert traversal: KV block outer loop; query batches inner loop.
  2. Repair the side effects: gather non-contiguous queries, reduce partial outputs, and compute online-softmax statistics safely.
  3. Account for total cost: analyze memory access and FLOPs including the extra kernels.
  4. Test end-to-end: H20/H200, multiple GQA groups, NSA settings, LLMs, and context lengths.
§1 p.2 · §3-4 pp.4-10
BASELINE

NSA selected attention: efficient sparsity, awkward scheduling

NSA kernel
  • Outer loop: one query token, batch query heads that share KV heads.
  • Inner loop: iteratively load selected KV blocks.
  • Works well only if each GQA group supplies enough heads to fill a dense tensor-core tile.
FSA kernel
  • Outer loop: one KV block.
  • Inner loop: batches of query tokens that selected that block.
  • Usually many query tokens exist, so the tile is filled without padding.

FSA KERNEL DESIGN

Assign each thread block a (query head, KV block) pair

  • Load the KV block once, then iterate non-contiguous batches of query tokens that selected it.
  • The selection tensor yields Ii, the valid queries for block i; mapping Oi makes intermediate writes contiguous.
  • Early return after Ii is exhausted avoids loading or computing invalid work.
  • Backward pass reuses cached indices instead of rebuilding them.
§3.2 pp.4-5
CORRECTNESS

Inverting loops distributes one query across thread blocks

What breaks
  • Partial attention results for a query come from distinct KV blocks / thread blocks.
  • Writing directly to the output needs atomic additions.
  • Computing online-softmax statistics independently gives incorrect maxima and outputs.
FSA repair
  1. Selection kernel writes partial outputs to Obuf.
  2. Dedicated online-softmax kernel precomputes statistics.
  3. Dedicated reduction kernel accumulates and scales final output.
The separate kernels are mandatory correctness machinery, not optional optimization.
§3.2 pp.5-6
COST MODEL

Extra kernels are cheaper than NSA padding at common GQA settings

FSA memory = dN(6h + 2hK)(1 + T)
FSA FLOPs = dNBKT(4h + 2hK)
  • The formula counts selection, online-softmax, and reduction kernels together.
  • At length 64K and (BK, T) = (64, 16), GQA=4: FSA estimates 21.3% of NSA memory access and 56.2% of NSA FLOPs.
  • The comparison is strongest where NSA otherwise pads up to 8 query heads.

ACCURACY CHECK

Kernel substitution does not visibly destabilize training

  • Llama3-8B fine-tuning shows FSA, NSA, and full attention with stable and similar convergence curves.
  • Additional Llama-3.2 1B/3B and Llama-3.1 8B LongBench experiments report loss, perplexity, and QA F1 across MQA, SQA, and synthetic tasks.
  • The paper characterizes FSA as preserving NSA/full-attention accuracy; this deck does not infer stronger accuracy superiority.
The evidence supports implementation correctness, not a new modeling-quality claim.
Appendix D pp.14-15 · Fig.11 p.15 · Tables 2-4 pp.15-16
TRADE-OFFS

FSA swaps padding waste for irregular access and buffers

  • Non-contiguous query loads reduce cache-friendly coalescing; the real-hardware gain is therefore smaller than the FLOP-model gain.
  • At 64K, T=16, d=128, the illustrative Obuf consumes 1 GB HBM.
  • Profiled buffer overhead reaches 5.01 GB at 128K and 12.36 GB at 256K for (64,16).
  • An attention-sink first KV block needs special dual-buffer allocation because it is dense.
Appendix E pp.17-18
DEPLOYMENT RULE

Use online profiling rather than treating FSA as a universal replacement

  • On first use of a hyperparameter set, FSA profiles candidate query-batch sizes such as 1, 64, and 128.
  • When GQA is large enough, batch size 1 can serve as a fallback to the original NSA strategy.
  • Cache the fastest choice for subsequent calls with the same hyperparameters.
The paper’s own deployment story is conditional: profile, select, cache.
Appendix E p.17
ENGINEERING TAKEAWAYS

Three lessons for attention-kernel work

  1. Match the parallel axis to hardware tile constraints. A sparse algorithm can need a different traversal to become fast.
  2. Price in correctness and memory plumbing. Reductions, softmax statistics, index maps, and buffers are part of the design.
  3. Measure at multiple levels. Microkernel wins need kernel, end-to-end, ablation, and accuracy checks before they are deployment claims.

Three compact excerpts worth retaining

“FSA exchanges NSA kernel loop order and processes query heads one by one, looping over KV blocks in the outer loop and batches of query tokens in the inner loop.”

FSA 交換 NSA kernel 的迴圈順序：外層走 KV blocks，內層才批次處理 query tokens。§3.1 p.4

“the token selection phase dominates overall attention computation performance, accounting for up to 79% and on average 65% of total attention overhead.”

token selection 是主要瓶頸：最高佔 79%，平均佔 65% 的 attention overhead。§4.4 p.9

“FSA trades lowered memory access volume and FLOPs with non-contiguous loading and more buffer overhead.”

FSA 用較少 memory access 與 FLOPs，交換 non-contiguous loading 和額外 buffer 成本。Appendix E p.17

The sparse algorithm was not the bottleneck. Its loop order was.

FSA shows how a kernel-level schedule can unlock existing long-context sparsity for the GQA configurations modern LLMs actually use.
