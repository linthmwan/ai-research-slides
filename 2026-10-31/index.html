CORAL：讓 Agent 自己整理工作記憶

Don't Lose the Thread: Empowering Long-Horizon LLM Agents with Cognitive Resource Self-Allocation
Zheng Zhu, Xiaozhuan Liang, Xi Chen, Bei Yu, Jiaya Jia · CUHK / Tencent / HKUST
COLM 2026arXiv 2610.40350v1 · 2026-10-29

Venue：PDF 每頁頁首「Published as a conference paper at COLM 2026」· 程式碼 github.com/JIA-Lab-research/CORAL · 選題：daily_discover 週六清單中 ★ COLM accepted · Reviewer 資料：未抓取

TL;DR

長任務 agent 的 context 會被工具輸出塞爆。CORAL 給 agent 兩個工具：MM 把進度與已驗證事實寫成 checkpoint，CO 清空 context、只帶 checkpoint 重開。SFT + 多 episode RL 後，Qwen3-8B 在 GAIA 拿 42.8%，輸入 token 比 ReAct 少 6–7×；不需訓練，就讓 Claude Sonnet 4 在 BrowseComp +8.0。

Abstract, p.1
問題

ReAct 迴圈的 context 只增不減

  • 每輪 Thought → Action → Observation 都留在 context：冗長的網頁回饋、失敗的嘗試全部累積
  • 雜訊越多，規劃與推理越差；作者類比人類工作記憶飽和時的「認知超載」
  • 惡性循環：規劃不佳 → 呼叫產生無關回饋 → context 更亂 → 推理更差
ct = (s, q, r1, a1, o1, …, rt−1, at−1, ot−1)

s：system prompt；q：問題；r / a / o：thought / action / observation。ReAct 每一步都以完整歷史 ct 為條件。

§1, p.1–2；§2.1 eq.(1), p.3
前人缺陷

既有 context 管理：由規則觸發，不由 agent 判斷

路線代表問題
固定間隔壓縮Mem1（每次 function call 後壓縮）排程僵硬，可能丟掉有用資訊、打亂高層規劃
快滿時截斷 / 壓縮外部模型摘要、直接截斷時機與任務狀態無關
處理固定長輸入MemAgent針對靜態長文件，不處理互動中動態長出的 context
Agentic RLSearch-R1 類長任務 reward 稀疏，中間動作難以 credit assignment
CORAL 的立場：何時整理記憶，應該由 agent 依任務狀態自己決定。
§1, p.1–2；§5, p.10
動機

從認知心理學借來的設計：cognitive offloading

  • Kahneman (1973)：注意力是有限資源，要在競爭需求之間分配
  • Baddeley & Hitch (1974)：工作記憶是小而需要主動維護的儲存
  • Sweller (1988) 認知負荷理論：要記住的東西超過容量，即使每一步都不難，表現也會變差
  • 人類的解法：把中間狀態寫下來（offloading），把內部容量留給眼前的子問題
對 LLM agent：context 就是工作記憶 → 讓 agent 把進度寫到外部，再清掉被 checkpoint 摘要過的 context。
§3, p.3

Figure 1, p.2
方法 · 工具 1

Memory Management（MM）：寫 checkpoint

  • 兩類持久資訊：task progress（高層計畫、各子目標是否完成）與 verified facts（已確認的中間結果、找到的實體）
  • 可新增、修改、刪除；checkpoint 在 context 重置後仍然存在
  • 三個典型呼叫時機：任務開始時寫計畫；發現關鍵資訊時存成事實；完成子任務後更新進度
  • 關鍵：由 agent 自己判斷何時呼叫，不是規則或外部控制器觸發
§3.1, p.3–4
方法 · 工具 2

Context Optimization（CO）：硬重置，開新 episode

at = aCO ⇒ ot = memory state； ci = (s, q) if i = 1， ci = (s, q, oi−1, Mi−1) if i > 1
  • agent 判斷 context 過長或充滿過時資訊時呼叫：清空對話歷史，把目前記憶當成 observation 回傳
  • 下一個 episode 只看得到 system prompt、問題與 checkpoint；累積的工具輸出與推理痕跡全部丟棄
  • 整條軌跡 T = (e1, e2, …, eN)；只有最後一個 episode 的最終 thought 含答案
§3.1, eq.(2)–(4), p.4
訓練 · 階段 1

SFT：把軌跡切成 episode，各自當訓練樣本

L = − (1 / Σi I(xi ≠ o)) · Σi I(xi ≠ o) · log πθ(xi | x<i)
  • 每個 episode 的初始 context 不同，接成一段平坦對話會與推論時看到的不一致，所以必須切開
  • loss 只算 agent 自己產生的 token（thought、tool call），observation 被 mask 掉
  • 非末段 episode 教「維護記憶，並判斷何時該 reset」；後段 episode 教「從 checkpoint 接續、不重做已完成的工作」
  • 用一般單 episode ReAct 軌跡訓練，這兩種情境都不會出現
§3.3, eq.(5), p.4–5
訓練 · 階段 2

Multi-episode ARPO：reward 跨 episode 廣播

Rij = Ri ∀ j ∈ {1, …, Ni}； Âij = (Ri − mean(R)) / std(R)
  • 以 DAPO 為基礎：每個 episode 是獨立的最佳化單位，token-level 平均、clip εlow = 0.2 / εhigh = 0.28
  • 同一題的 G 條軌跡、所有 episode 一起做 normalize → 同軌跡的 episode 共享 advantage
  • Reward：R = Rformat × Ranswer（JSON 格式合法 × LLM-as-judge 判對錯）
§3.3 eq.(6)–(9), p.5–6；App. A.2 Tab.6, p.14
實驗設定

資料：Claude Sonnet 4 + CORAL 合成，對錯軌跡都保留

  • 題目依 WebShaper 方法合成（可控推理深度），與所有測試集獨立
  • 2,932 條 web 軌跡：1,642 條答對（56%）、1,290 條答錯（44%），只過濾格式
  • + 241 條數學推理軌跡（NuminaMath、OpenMathReasoning）→ 共 3,173 條，切 episode 後 3,682 段對話
  • 模型 Qwen3-8B：SFT 全參數 3 epoch、lr 1e-5、max len 65,536；RL lr 1e-6、每題 8 samples、最多 50 輪、無 KL

評估：GAIA text-only val 103 題（L1 39 / L2 52 / L3 12）；每題 8 次取樣，temp 0.7、top-p 0.8，報 Pass@1 = Avg@8。工具：Web Search、Web Browse + MM、CO。

機制 · 記憶腐化實驗

CO 會關掉自我稽核的通道

竄改時機結果原因
剛寫完計畫照單全收，執行到底還沒有任何證據可以對照
中途竄改已驗證事實常被發現（不穩定）產生該事實的搜尋結果仍在 context
CO 之後竄改永遠救不回支撐證據已隨 reset 被丟棄
對話歷史不只是冗餘，而是交叉驗證通道。MM 保留歷史、可以多用；CO 放棄自我稽核能力、應該少用——訓練後 3.9 次 MM vs 0.21 次 CO 正好符合。

此實驗為定性觀察，論文未提供腐化率曲線。

局限

讀這篇要注意的幾點

  • Reward 平均廣播：好的鋪路 episode 與失敗的繞路拿同樣獎勵，和論文動機有張力；作者認為單純折扣早期 episode 也不對，需要 episode 層級的品質指標
  • 記憶不可質疑：checkpoint 一律被當成事實；作者建議 provenance-aware memory（每個事實附上證據來源）
  • GAIA L3 只有 12 題：一題就是 8.3 分，std 9–10%，只能當方向性證據
  • 驗證範圍窄：BrowseComp 只跑前 150 題、單一 backbone；SFT / RL 只在 Qwen3-8B（另有一次 Qwen2.5-7B SFT）
  • 比較條件不同（編者觀察）：CORAL 的 SFT 資料由 Claude Sonnet 4 蒸餾而來；8B 平均仍略低於 CK-Pro-8B
App. E, p.19–20；Table 1, p.7
解讀

對做 agent 系統的工程師有什麼用（編者解讀，非論文結論）

  • 最便宜的試法：不訓練，只給強模型加 MM / CO 兩個工具（論文的 prompting-only 結果），在長鏈瀏覽任務上就有明顯收益
  • MM 與 CO 不對稱：「寫筆記」幾乎沒有代價，「清空 context」會失去自我稽核能力 → 實作時 reset 應保守，checkpoint 可積極
  • Checkpoint 顯式記錄推理的依賴結構：遇到死路時，能回頭檢查前提，而不只是換關鍵字重搜
  • 小模型的瓶頸在工具呼叫格式；要在 7–8B 上用，SFT 幾乎是必要的

此頁為編者推論，已與論文內容分開標示。

附錄 · 原文對照

核心機制

CO resets bound how long the context may ever become ... Less directly but more powerfully, an agent that has written down its plan and verified facts stops re-searching what it already knows, cutting turns threefold.

CO 重置限制了 context 的最大長度……而更間接、但效果更大的是：把計畫與已驗證事實寫下來的 agent 不會重搜已經知道的東西，輪數因此降為三分之一。§4.3, p.8

Training teaches the model not to reset more but to checkpoint better.

訓練教會模型的不是更常 reset，而是把 checkpoint 寫得更好。§4.3, p.8

附錄 · 原文對照

為什麼 MM 與 CO 不對稱

The conversation history is not merely redundant with the memory store; it functions as a cross-validation channel, and CO closes that channel permanently for everything the memory currently holds.

對話歷史並不只是記憶庫的冗餘副本，它是一條交叉驗證通道；而 CO 會對記憶中所有內容永久關閉這條通道。App. D.2, p.19

behavior cloning on masked agent outputs supervises the process rather than the conclusion

在遮罩後的 agent 輸出上做行為複製，監督的是過程而非結論。§4.5, p.9
