SageAttention2

用 Q/K INT4 + P-tilde/V FP8，讓 attention kernel 變快，但不把模型品質一起量化掉。

THE THESIS

真正的難點不是把 attention 壓到 4-bit；而是讓 quantization granularity、tensor-core layout、accumulator 同時對齊。

SageAttention2 的核心是 hardware-aware error control，不是單純換更小的 datatype。
Abstract p.1 · §3 pp.4-6
01 · WHY ATTENTION IS STILL EXPENSIVE

FlashAttention 減少 IO，但 QK^T 與 PV 仍是 N²d 的兩個大 matmul

  • Exact attention 仍需 QKT 與 PV；兩者各自是 O(N²d)。
  • Linear/sparse attention 會改變計算或適用範圍；硬體取向的 exact attention 則保留完整計算。
  • 前代 SageAttention 的 INT8 QK^T + FP16 P-tilde/V 還沒吃到 INT4 與跨 GPU 的 FP8 throughput。
§1 p.1 · §2.1 p.3 · Table 1 p.3
02 · FAILURE MODES

直接降到 INT4 / FP8，會先被 outlier 與 accumulator 精度反噬

  • INT4 範圍只有 [-7,+7]；outlier 會讓大量較小元素變成 0。
  • per-tensor INT4 在 CogVideoX 會產生模糊輸出；Llama3 的 MMLU 可跌到 random-guess 25%。
  • Ada / Hopper 的 `mma(f32,f8,f8,f32)` 有效 accumulator 被量到是 FP22。
  • 所以 FP8 P-tilde/V 的誤差不只來自 input format，也來自累加路徑。
§1 p.2 · §3.4 p.6
03 · CONTRIBUTIONS

三個 error-control 元件，包住兩個低精度 matmul

  1. INT4 Q/K + FP8 P-tilde/V：4b 與 Hopper 用的 8b kernel。
  2. Smooth Q/K：先移除 token-axis mean，再用 GEMV 補回 softmax 相關分量。
  3. Per-thread quantization：quantization group 直接對準 `mma.m16n8k64` 的 thread layout。
  4. Two-level accumulation：block 內忍受 FP22，跨 block 回到 FP32 buffer。
§3 pp.3-6 · Table 3 p.8
04 · BASELINE EQUATION

方法不改 attention graph；它改的是每個 tile 的算術與 correction

S = QKT / sqrt(d)   ·   P = softmax(S)   ·   O = PV
  • FlashAttention 將 Q/K/V 切成 tiles，以 online softmax 維持穩定的 state。
  • SageAttention2 保留同一個 streaming recurrence；因此不是 sparse/linear attention 的替代品。
  • 設計目標：把 QK^T 移到 INT4、P-tilde/V 移到 FP8，同時保存 end-to-end metrics。
§2.1 p.3 · §3 p.3
05 · SMOOTH BEFORE INT4

先中心化 Q/K，讓 INT4 的少量碼位不被 outlier 霸佔

關鍵不是「量化得更細」，而是先把量化誤差的來源移走。
Fig. 2 p.4 · §3.1 p.4
06 · Q/K SMOOTHING MECHANISM

mean removal + 一個 GEMV correction，避開重建全精度 score

gamma(Qi) = Qi - qbari   ·   gamma(Kj) = Kj - kbar   ·   Sij = INT4-GEMM + Delta Sij
  • 只需補 `Delta S = qbar_i gamma(K_j)T`；同一 row 的 common bias 在 softmax 後會消失。
  • smoothing、quantization、GEMV 可融合成一個 preprocessing kernel，off-chip Q/K 只讀一次。
  • 這是 attention-specific 設計：QK^T 的 quantization 軸限制讓 generic per-channel quantization 不適用。
§3.1 p.4 · Eq. 2 p.4
07 · GRANULARITY IS AN ISA DECISION

Per-thread scale group 對齊 tensor-core instruction，而非照教科書切 tensor

  • Q block 分給多個 warp；每個 32-thread warp 執行 `mma.m16n8k64`。
  • 每個 thread 在 dequantization 對應一個 scale，不用處理 per-token 的 scale-vector dot product。
  • 更細：比 per-block 更能隔離 outlier。
  • 更快：避免 per-token scale 的延遲。
  • 本質：把 accuracy granularity 與 execution mapping 綁在一起。
§3.2 p.5 · Fig. 4 p.5
08 · FP8 IS NOT THE WHOLE STORY

P-tilde/V 選 FP8 E4M3；真正補洞的是 FP22-to-FP32 two-level accumulation

  • P-tilde 在 [0,1] 且有大量小值；E4M3 比 uniform INT 更適合保留它們。
  • E4M3 的 CogVideoX layerwise cosine similarity 是 99.44%，FP16 為 99.45%，INT8 僅 77.05%。
  • 每個 block product 先在 effective FP22 tensor-core accumulator 內完成，再併入 FP32 `O_ij` buffer；作者以 `b_k = 64` 限制局部累加範圍。
§3.3 pp.5-6 · §3.4 p.6 · Table 7 p.9
09 · ALGORITHM VIEW

一個 tile 的工作順序：center → scale → low-precision MMA → correct → accumulate

  1. K 做 mean removal；V 做 per-channel FP8 quantization。
  2. 每個 Q block 做 per-thread INT4；每個 K block 做同樣的 mapping。
  3. INT4 MMA 後加入 GEMV Delta S，得到 online softmax 所需 score。
  1. P-tilde 乘 448 並轉 FP8 E4M3。
  2. block 內 product 先進 FP22；跨 block output 留在 FP32。
  3. 最後以 online-softmax normalization 與 V scale 還原。
Algorithm 1 p.6

為什麼 Q+K smoothing 是主因：它讓 INT4 重新看見大多數 activation

Smoothing 不是微調；它把 INT4 從 outlier-dominated representation 拉回可用的 numerical regime。

17 · WHERE IT DOES NOT GENERALIZE

這不是「所有 GPU、所有模型都直接 INT4」的故事

  • Hopper 沒有 native INT4 tensor core，因此使用 8b variant，且不含 Q smoothing。
  • V smoothing 只在 V 有 channel-wise bias 時明顯有利；作者沒有在 main experiments 使用它。
  • 4b 的可視品質仍可能有 minor differences；8b 才是作者定位的 near-no-loss 路線。
  • 證據來自 NVIDIA CUDA kernels 與選定模型；原文沒有建立跨 vendor ISA 的 portability claim。
§3.4 p.6 · §4.1 p.8 · §4.3 p.9
18 · ENGINEERING TAKEAWAYS

把這篇放回 kernel / compiler 工作：三個可移植的設計問題

  1. 先找 error source：outlier、scale granularity、還是 accumulator？不要把它們全叫「quantization error」。
  2. 把 numerical choice 綁到 ISA：scale group 可以由 MMA layout 決定，而不是只由 tensor dimension 決定。
  3. 把 throughput 與 end-to-end 分開驗：kernel 3x 不等於整個模型 3x；同時記錄 quality task。
  4. 不要相信 type name：實測 MMA accumulator 的 effective precision，才知道 correction 要放在哪裡。

FP8 kernel 的隱藏現實：effective accumulator 是 FP22

“We find that the accumulator for the mma(f32f8f8f32) instruction on the Ada and Hopper architecture is actually FP22.”

名稱看起來像 FP32 的 MMA accumulator，實際有效精度是 FP22；所以跨 block 需要 FP32 buffer。§3.4 p.6
