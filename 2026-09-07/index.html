Headroom-Drift Replay: A Primitive for Principled Replay Control in GRPO

Hyun Bin Park · Du-Seong Chang · Sogang University
COLM 2026 conference paperarXiv 2609.03941v1 · 2026-09-03

把 GRPO replay 從「要不要重用」拆成 learning value 與 current-policy compatibility 兩個控制問題。

TL;DR

Replay 不是多塞舊資料。它要先問：這個 group 還有沒有可學的方向，而且現在的 policy 還認不認得它。

Headroom 排 learning value；Policy Drift 擋 stale groups；fresh on-policy rollout path 完全不改。
Abstract p.1; §1 p.2; §3.1 p.3-4
問題設定

LLM RL 的瓶頸不是 update，而是一直重新 rollout。

  • GRPO-style post-training 需要 repeated fresh rollout generation；agentic setting 還要跑外部環境，wall-clock cost 更高。
  • Naive replay 只說「把舊 trajectory 拿回來」，但沒有判斷它是否仍有 learning signal。
  • Stored group 可能「仍有價值但太 stale」，也可能「很接近 current policy 但已經沒什麼可學」。這兩種失敗要拆開。
這篇的乾淨之處：它把 replay-side control 單獨拿出來，不靠額外 exploration / filtering pipeline 混淆貢獻。
§1 p.2; §2 p.3
核心貢獻

一個 replay primitive，四個檢驗角度。

  1. Formulation: GRPO replay = learning-value prioritization + current-policy compatibility。
  2. Primitive: Headroom-Drift Replay，group-level，fresh on-policy stream unchanged。
  3. Baselines: matched/larger on-policy、matched/larger recency replay、DAPO、ExGRPO、BAPO。
  4. Evidence: math / agentic / multimodal 三域，加上 same-buffer counterfactual、lifetime exposure、entropy-collapse analysis。
§1 p.2; §4.1 p.6-7; §4.3 p.9-10

Method · state

Replay 的單位是 full group，保留 GRPO 的 within-group comparison。

Stored group

  • prompt Q + n responses: g=(Q,G1,...,Gn)
  • response-level advantage Ai 套到同一 response 的所有 generated tokens
  • buffer 儲存 actions、generation-time log-probs、advantages 與 πgen(g)

Same update form

ri,j(θ;g)=πθ(ai,j|si,j) / πgen(g)(ai,j|si,j)

Fresh 與 replayed groups 都進同一 GRPO objective；差別只在 denominator 是哪個 reference policy。

§3.2 p.3-4
Method · Headroom

Headroom 排的是「還有多少方向性修正空間」。

hi,j=1-π(a|s) if Ai>0; hi,j=π(a|s) if Ai<0; Headroom(g)=mean(i,j) hi,j
  • Positive-advantage token 若目前機率仍低，還有往上推的空間。
  • Negative-advantage token 若目前機率仍高，還有往下壓的空間。
  • 以 generation-time policy 評估時，這個值成為 buffer 裡的 cached / stored priority。
§3.3 p.4
Method · Policy Drift

Drift gate 擋的是「現在的 policy 已經離當初 rollout 太遠」。

Δi,j=log πθ(ai,j|si,j) - log πgen(g)(ai,j|si,j); Drift(g)=mean Δi,j2
  • 只在 stored token sequence 上量 current-policy mismatch。
  • 用 squared aggregation 避免 signed average 的正負抵消，也更懲罰局部大 mismatch。
  • 通過 gate 時，current-policy Headroom 與 stored priority 的偏差被限制在約 √τ。
§3.4 p.5; Appendix A.3 p.16-18
Algorithm

Headroom 排序，Drift 掃描，填滿 replay budget 就停。

  1. Generate fresh grouped rollouts and compute GRPO rewards / advantages。
  2. 把 pre-existing buffer groups 依 Headroom descending 排序。
  3. 逐個 teacher-forced reevaluate stored actions；Drift(g)≤τ 才 admit。
  4. Accepted replay groups Rt 與 fresh groups Gont 混成 actor batch。
  5. Update 後才 append new ingress groups，FIFO eviction；避免 same-step replay。
Replay 不跑新的 autoregressive generation；agentic 場景裡省掉的正是外部互動成本。

Mechanism crown page

Mechanism · lifetime exposure

Headroom 真的改變 lifetime replay pressure。

Headroom <0.8: Nrep <0.5P(replay>=1) <24%Headroom >0.8: Nrep ≈2.0P(replay>=1) >56%
  • 低 Headroom groups 仍可能進 replay，但機率與次數都低。
  • 高 Headroom groups 被反覆重用，形成 exposure concentration。
  • 因此 selection 不是一次性 include/exclude，而是重新分配 lifetime training exposure。

Engineering gotcha

Reward semantics 會改變 replay ingress；Geo3K 是警告。

  • Geometry3K final reward 同時反映 answer correctness 與 formatting quality。
  • 原本 binary setting 的 s+i=1[ri>0] 不再等價於 correctness。
  • 錯答案但 format success 得 0.1；正答案但 format failure 得 0.9。直接沿用 success-count rule 會讓 ingress dynamics 變質。
ConditionFinal reward
wrong answer + format failure0.0

Limits

這篇夠乾淨，但不要把結論推過界。

  • 7B Search-R1 scale check 是 one run per method；小差距要當 controlled evidence，不是統計定論。
  • τ 還是要 coarse calibration；tight / loose 都會失效，不是無參數方法。
  • late-stage usable replay mixture 會收縮；mechanism 不是 collapse-free guarantee。
  • 作者只給 preliminary CISPO-style evidence；PPO / GSPO / CISPO family 的 held-out evaluation 仍 open。
Tab.6 p.21; §5 p.10; Appendix E.4.2 p.36-37; Appendix G.2 p.45-48
工程解讀

把 replay 做成可診斷 primitive，比把整條 pipeline 加厚更有用。

  1. 可分離：Headroom/Drift 對應兩個失敗模式，便於 ablation 與 debug。
  2. 可監控：acceptance rate、replay KL、source-age mixture 可以 early-stop 壞 τ。
  3. 可組合：它不是取代 EFRame / ExGRPO / BAPO，而是可嵌入那些 replay-centric systems 的 control layer。
  4. 對 agentic RL 特別實用：teacher-forced reevaluation 比 fresh environment interaction 便宜。
§3.5 p.5-6; §5 p.10; Appendix G.2 p.45-48
Appendix · highlight

作者自己把問題講得很準。

The question is not whether to replay, but how to control replay itself: which stored experience should re-enter training, and under what conditions.

問題不是要不要 replay，而是 replay 本身該怎麼控制：哪些 stored experience 應該重回訓練，以及在什麼條件下重回。§1 p.2

The fresh on-policy stream remains unchanged... Any change in training dynamics therefore traces to replay-side control alone.

fresh on-policy stream 不變；因此訓練動態的變化可歸因於 replay-side control。§3.1 p.3-4

Appendix · highlight

Replay 的真正價值是重新分配 exposure。

Replay selection is not merely deciding one-shot inclusion versus exclusion; it is redistributing lifetime training exposure toward a comparatively small subset of repeatedly reused groups.

replay selection 不只是一次性納入或排除，而是把 lifetime training exposure 重新分配給少數會被反覆重用的 groups。Appendix D.4 p.31-32

At matched score levels, both low-entropy entry and rebound are delayed under replay.

在 matched score level 下，replay 讓 low-entropy entry 與 rebound 都延後。Appendix E.3.2 p.35
