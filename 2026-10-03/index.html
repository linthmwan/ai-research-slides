KaliBench

細粒度評估：LLM 能不能把資安 analyst 的意圖，寫成真的可執行的 Kali Linux CLI command？

NeurIPS 2026 · E&D Track2026-10-01
Pengfei Li · Naufal Suryanto · Sicheng Zhang · Muzammal Naseer
Khalifa University · University of Western Australia
Paper: KaliBench: A Fine-Grained Benchmark for Cybersecurity Tool Use on Kali Linux with Runtime-Free Verifiable Rewards · arXiv:2610.02206
TL;DR

把 tool 選擇、optional flags、positional args 拆開量，才看得見 agent 到底在哪一步把 command 寫壞。

同一組可驗證 component labels 還能直接做 runtime-free RL reward。
Abstract p.1 · §3 p.4–6
WHY THIS BENCHMARK

資安 tool use 不是一般 function calling

CLI 沒有乾淨 schema

  • Kali Linux 有超過 2,000 個 pre-installed security tool packages。
  • 把數百個 tool schema 都塞入 prompt，不是一般部署的可行假設。
  • flag spelling、value binding、alias 或 positional order 一個錯，就可能無法執行。

端到端 agent benchmark 也不夠

  • CTF / agentic task 將 planning、environment、observation、tool invocation、recovery 混在一起。
  • 最後分數很難歸因到「模型是否會寫 command」。
  • KaliBench 刻意 isolating command generation。

DATA CONSTRUCTION

27.7K 初稿，最後只留下 8,504 個可用 pairs

  1. Official manuals：2,372 tools 的 Markdown documentation，Qwen3-Max 每 tool 生成 10–13 pairs。
  2. LLM verifier：對照 query、command、manual；第一輪後 53.8% examples 被濾掉。
  3. Sandbox execution：在 Kali Docker 觀察 stdout/stderr/exit code，繼續移除 invalid args。
  4. Human-in-loop + SemHash：針對 hinted mode 仍失敗案例審核，再以 cosine > 0.90 clustering 做語意去重。
§3.1–3.2 p.4–5
QUALITY GATE

Grounding manual 仍不等於 ground truth

>50%

初步人工檢查中，generated commands 含 hallucinated / misspelled options。
  • LLM-only verification 仍漏掉錯誤；sandbox 是第二道。
  • Human review 聚焦「最強模型有 docs 仍失敗」的樣本，分辨 data error 與 model limitation。
  • 最終 8,504 pairs 約為初始 27.7K 的 30.7%。
這個 benchmark 的價值不是生成量，而是每一層可追溯的 verification。

THREE MODES

同題目、不同資訊量：把 error source 拆開

Mode模型拿到什麼主要在測什麼
Unrestricted只有自然語言 query自己找 tool + 寫 args
Restrictedquery + 含正解的 20 tool namestool selection ambiguity 降低後，args 還會錯嗎？
HintedRestricted + official docs有 schema-like hint 後能否寫對？
Restricted 不是 Hinted 的弱版；兩者各自 isolate 不同 failure source。
§3.3 p.5
SCORING

評分不用 execute candidate command

Parser

  • Python shlex 做 UNIX shell lexical parsing。
  • optional args：alias-aware、順序可變。
  • positional args：值與順序都要匹配。

Metrics

  • Tool Accuracy
  • Optional-Argument F1
  • Positional-Argument F1
  • Total Score = component scores 的 mean
  • Exact Correct = 全部 component 完全符合

TRAINING MECHANISM

為什麼叫 runtime-free？

Reward = rtool + ropt_args + rpos_args + rexact + rformat
  • 3,504 train pairs x 3 prompt modes = 10,512 training samples。
  • SFT 直接以 ground-truth command 為 target；GRPO 產出 reasoning + command。
  • 因 ground truth 在 data construction 已 sandbox-validated，reward 比對 structure 即可，不必執行 model output。
省下 runtime 的代價是：canonical label 的品質成為整條訓練訊號的地基。

FAILURE MODES

模型不是只會「選錯 tool」；它會把 CLI grammar 寫壞

  1. long / short alias 混用：例如同時混入 `--domain` 和 `-d`。
  2. option hallucination：把 positional value 當 flags，或 invent 不存在的 alias。
  3. hallucinated long options：只有 short flag 的 tool 被補出不存在的 long form。
  4. option name drift：`--symlink` / `--symlinks` 之類 singular-plural confusion。

LIMITATIONS

這是一個受控 abstraction，不是 production execution 的替身

  • Kali manuals 會隨版本新增、deprecate、rename 或 reinterpret flags；canonical ground truth 可能過時。
  • manual 本身可矛盾；alias-aware scoring 也難收盡 historical、distribution-specific、community variants。
  • LLM verifier + random human audit 仍可能有 residual errors。
  • 任務只涵蓋 single-command translation，尚未處理 multi-step workflows、retrieval、environment feedback。
§5 p.10 · Appendix O p.35–36
ENGINEERING TAKEAWAY

如果 agent 的 action 是 CLI，評估不該只問「任務做完了嗎？」；還要問：它是否選對 tool、綁對 argument、保住可執行 grammar？

將 structured intermediate checks 做成 benchmark 與 verifiable reward，可以把 agent failure 變得可診斷、可訓練。
§3–5 p.4–10
