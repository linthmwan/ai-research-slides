THE DEPLOYMENT GAP

Chinchilla answers how big? — not what shape?

  • Classic scaling laws model loss from parameter count N and training tokens D.
  • They omit deployment-time inference cost, which the paper identifies as a central practical expense.
  • A prior inference-aware law needs a model's total lifetime output tokens — unknowable before deployment.
  • The missing decision variable is architecture: width, MLP/attention split, and KV-head grouping.
The target is fixed-budget accuracy + throughput, not training loss alone.
§1 p.2; §2 p.3
MOTIVATING COUNTEREXAMPLE

Parameter count does not order serving speed

  • The 1.5B Qwen2.5 variant can be faster than 0.6B Qwen3 in the paper's comparison.
  • The explanation is architectural: higher hidden size, GQA, and MLP-to-attention ratio.
  • So an aspect ratio by itself is not a sufficient predictor of inference efficiency.
N is a budget; architecture decides how that budget is spent.
Fig.2 / §1 p.2
CONTRIBUTIONS

Four moves turn architecture into a search problem

  1. Condition Chinchilla-style loss on normalized hidden size and MLP-to-attention ratio.
  2. Train 200+ controlled variants, spanning 80M to 3B parameters.
  3. Optimize candidate architectures subject to a predicted loss constraint.
  4. Locally search GQA and validate at 1B / 3B against LLaMA-3.2.
Abstract p.1; §3.3–§3.4 p.5–6; §5.1 p.9
EXPERIMENTAL CONTROL

Hold the budget fixed; move the architecture knobs

Fixed within a parameter scale

  • Non-embedding parameter budget N_non-embed
  • Number of layers n_layers
  • Token budget D

Varied / searched

  • Hidden size d_model
  • MLP-to-attention ratio r = r_mlp/attn
  • Grouped-query attention (GQA)
Normalized width: d_model / sqrt(N_non-embed)
§3.1 p.3–4
THROUGHPUT ABLATION

Wider and more MLP-heavy can serve faster

  • On 8B LLaMA-3.1 variants, larger hidden size / fewer heads improve throughput across batch sizes.
  • Higher MLP-to-attention ratio also improves throughput at fixed width and budget.
  • GQA is tested separately because it affects serving strongly but its loss relation is not smooth.

MECHANISM · CROWN PAGE

Speed rises when attention work and KV-cache traffic shrink.

But accuracy has an interior optimum.

The study does not claim a free speedup: it makes efficiency gains admissible only while predicted loss stays below a target.

§3.2 p.4; Eq.4 / §3.4 p.6
LOSS LANDSCAPE · WIDTH

Normalized hidden size has a U-shaped loss curve

  • At fixed ratio and GQA, optima align across model sizes after width normalization.
  • Too-wide models reduce attention-head count and can degrade accuracy.
  • The law needs to locate the valley, not merely push width upward.
Fig.4 / §3.3 p.5
LOSS LANDSCAPE · ALLOCATION

The MLP-to-attention split also has a U-shaped optimum

  • Recent open models often allocate a smaller parameter fraction to attention as they scale.
  • The paper finds this trend is not universally optimal: either side of an interior ratio harms loss.
  • That turns the ratio from a hand-tuned convention into a fitted decision variable.
Fig.5 / §3.3 p.5
CONDITIONAL SCALING LAW

Use Chinchilla as a reference, then calibrate architecture

L_arch = f(d_model / sqrt(N)) x g(r_mlp/attn) x L_opt(N, D)

Step 1 · reference

  • Get optimal baseline loss L_opt(N,D) from a Chinchilla-style law.

Step 2 · architecture

  • Fit transparent U-shape factors c0 + c1 log(x) + c2/x for width and ratio.

The multiplicative and additive forms assume separable effects of width and ratio.

§3.3 p.5–6 · Eq.3 shown here in HTML-safe shorthand
SEARCH, NOT GUESSWORK

Constrained optimization closes the loop

maximize IN(P) subject to L(P | N, D) <= L_target
  1. Fit the reference and conditional loss law from smaller architectures.
  2. Solve for width and MLP-to-attention ratio under the loss target.
  3. Enumerate feasible GQA values and early-stop once below the GQA=4 baseline.
  4. Measure the Pareto candidates on the target serving stack.
GQA is handled as a discrete local search because its loss response is variable, unlike the smooth width/ratio trends.
§3.4 p.6 · Algorithm 1 / Eq.4
SETUP

The law is fitted small, then tested at larger scale

Pretraining sweep

  • LLaMA-3.2-style decoder-only models
  • 80M, 145M, 297M, 1B, 3B N_non-embed
  • Dolma-v1.7; 100 x N_non-embed tokens

Evaluation

  • vLLM, A100 40GB by default
  • 4096 input + 1024 output tokens
  • Five throughput repeats; zero-shot, nine lm-eval tasks

SERVING OUTCOME

The Pareto candidates stay faster across batch sizes

  • Surefire-1B and -3B satisfy loss targets matched to the LLaMA-3.2 baselines.
  • They achieve up to 42% higher throughput with vLLM on A100.
  • The paper also reports up to 47% higher throughput with SGLang on H200.
Fig.7 p.8; §5.1 p.9
FIT-DATA ABLATION

Fit closer to the deployment scale

  • For 3B, a fit using only 1B variants shows lower MSE and higher Spearman than the broad progressive fit.
  • Coefficients shift with scale; the law is useful, but not perfectly scale-invariant.
  • The authors suggest using a fitting scale around one-third of the target when possible.
Fig.8 / §5.1 p.9–10
INTERPRETATION

The useful output is not “make the model wider.”

It is a hardware-aware frontier between accuracy and serving cost.

The framework works because it separates a smooth accuracy model for width/ratio from an empirical discrete search over GQA and measured throughput.

§3.2–§3.4 p.4–6; §5.1 p.9
ROBUSTNESS CHECKS

Simple calibration wins; extreme ratios distort the fit

Outlier policy

  • Fit primarily over r_mlp/attn in [0.5, 5].
  • Including values such as 0.1 and 12.6 degrades Task-3 rank correlation.

Function-class policy

  • Multiplicative and additive calibration perform similarly.
  • More complex joint, non-separable alternatives do not improve prediction.
Prefer a calibrated, interpretable frontier over an overfit universal formula.
§5 p.8
LIMITS

What this paper has not established

  • No evaluation at 7B or beyond; the demonstrated scale stops at 3B.
  • The analysis is for dense models. MoE throughput is measured, but no MoE scaling law is fitted.
  • The study is about pre-training; post-training may change the accuracy–efficiency trade-off.
  • Inference efficiency depends on hardware and serving stack, so the objective is measured rather than purely analytic.
§7 p.10; §5.1 p.9
ENGINEERING TAKEAWAYS

A practical loop for model builders

  1. Benchmark the actual deployment stack before naming an architecture “efficient.”
  2. Sweep width and MLP/attention allocation under fixed parameter and token budgets.
  3. Fit only where the loss landscape is stable; validate extrapolation near the intended scale.
  4. Treat GQA as a constrained discrete serving choice, not a default inherited from a baseline.
Architecture search belongs beside data / compute scaling decisions — not after training has frozen the design.
Synthesis grounded in §3.1–§3.4 p.3–6 and §5.1 p.9
