Decoupling Planning and Control for Instructable Agents

Zineng Tang · Kelsey R. Allen · Sjoerd van Steenkiste · Ishita Dasgupta · Alane Suhr
COLM 2026 conference paperarXiv 2608.26788v1 · 2026-08-27Embodied VLM agents

把 slow VLM planning 和 fast world-model control 分開：VLM 只產生稀疏語言指令，controller 以控制頻率執行。

Source: cover p.1; Abstract p.1; Intro p.2
TL;DR

這篇的核心不是「讓 VLM 直接操控」，而是把 VLM 降成 planner，把低延遲動作交給可訓練的 controller。

結果：planner 可替換、multi-agent 可用語言協調，且不用把 VLM fine-tune 到每個低階 action space。
Abstract p.1; Intro p.2
Problem

VLM 會想，但低階控制太慢；world model 會動，但抽象指令太弱

  • VLM/VLA 能從視覺和任務文字產生 decomposition/subgoals，但直接輸出高頻、環境特定 action stream 很吃力。
  • Dreamer-style world-model controller 能從 pixels 做穩定控制，卻不容易用 open-ended language steering。
  • 多智能體任務還需要角色協商與溝通；純 controller 不處理語言，中央 planner 又容易成為瓶頸。
  • 作者的切入點：不要把「理解任務」和「每一步操作」塞進同一個模型。
Intro p.1–2; Overview p.3; §3.1 p.4
Contributions

Instruct-to-Act 的四個工程主張

  1. Planner-controller interface: pretrained VLM planner 產生自然語言 instruction；RSSM controller 接 observations + instruction embedding 產生 actions。
  2. Post-hoc instruction supervision: 用 VLM summarizer 替 on-policy replay segments 產生 instruction label，和 Dreamer losses 一起訓練。
  3. Asynchronous online inference: planner 在背景更新 draft plan；controller 不等 VLM，每一步照常執行。
  4. Language multi-agent coordination: controller 共享參數、各自 recurrent state；planner 透過 chatroom 協調。
Overview p.3; Method §3.1–3.4 p.3–6

Formal interface

用語言 instruction X 當 planner 和 controller 的邊界

πp: Ω → ΔX    /    πc: Ω × X → ΔA
x ~ πp(·|o),   ai ~ πc(·|oi, x)
  • X 是所有自然語言 utterances；planner 不需要知道環境的 primitive action vocabulary。
  • controller 在 instruction 尚未更新時可用 learned null embedding 或上一個 instruction 繼續行動。
  • 額外的 instruction-completion action/head 讓 controller 表示「現在可以要下一個 instruction」。
Overview p.3; §3.1–3.2 p.3–4
Mechanism crown

真正的效率增益來自 時間解耦：VLM latency 只影響「下一個高階指令」，不再影響「每一步控制」。

這也是為什麼 online planning 可以提高 throughput，卻不必犧牲 low-level execution。
§3.1 p.4; Table 9 p.17
Asynchronous inference

Online planner 在背景思考；controller 沒有 blocking step

Offline / blocking
  • controller 完成 instruction 後，等待 planner 產生下一個 instruction。
  • 每個 instruction boundary 都繼承 VLM latency。
  • Minecraft Diamond blocking steps mean = 35.4。
Online / asynchronous
  • planner 持續更新 memory bank + partial plan。
  • controller 完成時，planner 只需吐出少量 tokens。
  • Minecraft Diamond blocking steps mean = 0.0。
§3.1 p.4; Table 9 p.17
Multi-agent

多智能體不是訓練 centralized critic，而是讓 planners 用語言分工

  • 每個 agent 有自己的 planner instance 和 controller latent state；controller 參數共享。
  • planner 可收 peer messages、向 controller 下 instruction，也可對其他 agent 發訊息。
  • controllers 不讀 planner 間的 chat；協調壓力留在語言層。
  • Pico Park 中 decentralized communication 提升 task performance，同時維持與 centralized control 等同 throughput。
§3.1 p.4; §4.4 p.7; A.7 p.17
Controller architecture

Language-conditioned DreamerV3-style RSSM

Inputs / encoders
  • Visual features: CLIP-base-224 + DINOv2-base。
  • Language embeddings: MiniLM-L6-H384-uncased。
  • Frozen text encoder maps xt → et。
Policy/value conditioning
  • et 被投影後與 RSSM latent features concatenated。
  • policy/value heads 都 conditioned on `(st, et)`。
  • no-instruction path 使用 learned null embedding。
π(a|st, et) = Softmax(ℓ(st, et)/τ)a
§3.2 p.4; §4.1 p.6; A.3 p.15
Stop head

controller 何時完成 instruction，由一個 completion head 學出來

pstopt = σ(g(st, et))
  • actor output space 增加「instruction completed」indicator。
  • 每個被標註 replay interval 只有最後一步 `complete=1`。
  • 這個 head 是 asynchronous planner 的觸發點：完成時才要求下一個 instruction。
§3.2 p.4; §3.4 p.5
Training

Post-hoc annotation：不用 expert demos，把自己的 rollout 轉成 instruction labels

  1. 收集 on-policy rollouts 到 FIFO replay buffer，capacity |D|=1024。
  2. 抽取不重疊、可變長 interval；給 VLM summarizer 看 frames + action-sequence text。
  3. VLM 產生高階 instruction x；整段 interval 的 tuple 都配上 e，最後一步標 complete=1。
  4. 50% replay segments annotated；剩下未標註，保留 autonomous reward learning。
L = Lmodel + λVLvalue + λALactor + LBC + Lstop
§3.4 p.5–6; §4.1 p.6
Experimental setup

七個環境測的是「可插拔 VLM planner」而不是單一 domain trick

  • Environments: Atari, MineRL Minecraft Diamond, Crafter, DMLab, Overcooked, Pico Park, MindCraft。
  • 每組 100 episodes 或使用該任務標準 protocol；no exploration noise，temperature τ=0.8。
  • Main controller: 800M variant；GPT-4o annotates 50% replay segments。
  • 平均每環境訓練約 23 GPU-hours on 4 RTX A6000；annotation 額外 +17% GPU-hours / +12% slowdown。
§4.1–4.2 p.6; A.4 p.15

Claim boundary

控制 claim 在 matched ablations：不是說它打爆每個專用系統

  • 作者把 baselines 分成 reproduced、domain-adapted、contextual，避免把不公平比較當主張。
  • 最乾淨的證據是：同樣 planner 或 controller 條件下，移除 controller / 移除 instruction 都掉分。
  • GPT-4o sparse instructions + trained controller 在所有任務上優於 GPT-4o 直接產生低階 actions。
  • 與 JARVIS-1 等 Minecraft-specific 系統相比仍有競爭力，但論文主張重點是跨異質環境的 reusable recipe。

Failure mode

Multi-agent bottleneck 已經從 controller 轉移到 planner coordination

Limitations

這條路可用，但還不是 general-purpose embodied agent

  • 每個 environment 仍需訓練一個 800M controller；平均約 23 GPU-hours，一次 joint controller 在 Minecraft Diamond 掉 1.12 points。
  • asynchrony 帶來 instruction staleness：Minecraft 約 51 steps，Overcooked 約 165 steps。
  • vague instruction 會造成 locally suboptimal behavior，planner-controller alignment 還有空間。
  • 多智能體主要失敗來自 duplicated subgoals；語言溝通本身不是完整協調演算法。
§4.5 p.8; Table 9 p.17; A.5–A.7 p.16–17; Conclusion p.9
Engineering read

如果要做可落地的 agent system，這篇提醒的是：把 interface 做薄，不要讓 foundation model 卡在控制迴路最內層。

把 VLM 放在「可慢、可替換、可觀察」的位置；把高頻控制交給專門 controller。這比把所有能力硬塞進單一模型更可 debug。
