PROBLEM

現在的 agent memory 到底少了什麼？

  • Context dilution: 把大量歷史直接丟進 context，長程訊息會被稀釋。
  • Epistemic blur: 觀察到的事實、系統自己的經驗與主觀判斷常被混在同一種「memory」。
  • One-path retrieval: 只做 top-k similarity，容易漏掉跨時間、跨 entity 或因果鏈上的相關訊息。
  • Static persona: style 只是一次性 prompt，而不是會隨證據被追蹤與修訂的 belief state。
作者的立場：記憶層要是 reasoning substrate，不是一個附加的 RAG cache。

ARCHITECTURE

核心抽象：四個 networks 分開存放不同 epistemic status

  1. World W：外部世界的客觀 facts。
  2. Experience B：agent 自己做過、建議過的第一人稱經驗。
M = {W, B, O, S}
  1. Opinion O：主觀判斷 + confidence + timestamp。
  2. Observation S：從事實彙整出的、偏好中立的 entity profile。
關鍵不是多一個 vector DB；是讓 belief 不再冒充 evidence。
Sec.3.1 p.4 · Fig.1 p.4
THREE OPERATIONS

所有 state transition 都落在 retain、recall、reflect

  1. Retain(B, D)：把 transcript / document 轉成有時間、entity 與 link 的 structured facts。
  2. Recall(B, Q, k)：在 token budget k 下，取回多策略排序後的相關 memories。
  3. Reflect(B, Q, profile)：用取回 facts + behavioral profile 生成回答，必要時新增或更新 opinions。

資料寫入、檢索、主觀更新不再是同一段 prompt 裡的隱式副作用。

Sec.3.2 pp.4-5 · Sec.6.1 pp.16-17
END-TO-END

TEMPR 做 retain/recall；CARA 做 reflect

Fig.2 p.5 · Sec.3.3 pp.5-6
RETAIN

不是切碎句子，而是抽取可獨立理解的 narrative facts

  • 每段對話以 2-5 個 comprehensive facts 表示；保留人物、時間範圍、理由、fact type 與 entities。
  • 相較於 sentence-level fragments，整段 narrative fact 對跨 turn 的因果與語境更不敏感。
  • 每個 memory node 同時保存自然語言、embedding、發生時間、提及時間、type、confidence 與 metadata。
事實單位越完整，後續 retrieval 才不必依賴 prompt 內殘留的局部上下文。
Sec.4.1.1-4.1.2 pp.6-7 · Fig.3 p.7
GRAPH

Entity、time、meaning、causality：四種邊讓記憶能多跳

Entity resolution

  • string/name similarity
  • co-occurrence patterns
  • temporal proximity
  • shared canonical entity -> bidirectional links

Graph link types

  • temporal：時間接近度衰減
  • semantic：embedding similarity 過 threshold
  • entity：同一 canonical entity
  • causal：causes / caused_by / enables / prevents

因此，表面上不像 query 的紀錄，也可以沿著人、事件、時間或因果關係被找回。

Sec.4.1.3-4.1.4 pp.8-9
OBSERVATIONS

Entity profile 不是 opinion：它是可非同步重建的 factual summary

  • 對「Tell me about Alice」這類 entity query，直接讀 synthesized observation 可避免把所有 raw facts 重複塞回上下文。
  • Observation 由底層 facts 彙整，不受 behavioral profile 影響，也不帶 opinion confidence。
  • 新 facts 寫入後，以 background task 重建相關 entity 的 observation：降低 write latency，逐步提高 profile 品質。
Sec.4.1.5 p.9
RECALL

四路平行 retrieval：不要讓單一相似度定義 relevance

Direct relevance

  • Semantic：HNSW / vector cosine similarity
  • Keyword：BM25 回收 proper nouns 與精確術語

Relational relevance

  • Graph：從 semantic hits 出發做 spreading activation
  • Temporal graph：解析 query 時間，再限制 / 排序發生於該區間的 facts
這個拆法把「像不像 query」與「是否在關係/時間上必要」分開處理。
Sec.4.2.2 pp.9-10
FUSION

RRF + cross-encoder + token packing：從候選到 LLM context

RRF(f) = Σ 1 / (k + ranki(f))
  • Reciprocal Rank Fusion 只看 rank，不要求 vector、BM25、graph 分數彼此校準。
  • 同一 fact 在多個 channel 都排前面時，自然累積更強的 evidence。
  • cross-encoder 在候選集上再排序；最後依 token budget 由高到低裝箱，直到超過 k。
Sec.4.2.3-4.2.5 p.11
CARA

Reflect 把 persona 從一句 system prompt 變成可配置 profile

ParameterRangeStated behavioral effect
Skepticism1-5higher -> demands stronger evidence
Literalism1-5higher -> follows explicit wording closely
Empathy1-5higher -> weighs emotional/interpersonal context
Bias strength0-1controls profile influence on opinion formation
Sec.5.2.1 pp.11-12
OPINION STATE

同一份 facts，不同 profile 可以導向不同判斷；但判斷會留下可更新的 state

Fig.4 p.13 · Sec.5.4 p.13
BELIEF REVISION

Opinion confidence 有顯式更新規則，而不是在下一輪悄悄覆寫

  • 先用 entity overlap 或 embedding similarity 找出可能相關的 existing opinions。
  • LLM 將新證據判作 reinforce / weaken / contradict / neutral。
  • reinforce: c + alpha；weaken: c - alpha；contradict: c - 2alpha；必要時同步修正 opinion text。
  • 設計目標是避免單一新例子造成震盪，同時讓重複支持或強反證能改變 trajectory。
Sec.5.5 pp.14-15
MECHANISM / CROWN PAGE

報告最有說服力的機制不是「模型更大」。
同一個 OSS-20B，有 structured memory 時 LongMemEval 從 39.0% 到 83.6%。

尤其是 multi-session 21.1 -> 79.7、temporal reasoning 31.6 -> 79.7；這些正是 graph 與 time-aware retrieval 應該幫得上忙的類別。

WHAT IS MISSING

真正需要保留的保留：paper 沒有證明每個模組都必要

Evidence it provides

  • end-to-end comparisons on two long-horizon benchmarks
  • same-backbone LongMemEval contrast
  • explicit architecture and prompts in appendix

Evidence it does not provide

  • no ablation for graph vs temporal vs RRF vs reranker vs CARA
  • no filled-in retrieval token budgets: <add>
  • third-party baselines not independently reproduced
把它當作一個有清楚 system design 的實作報告，而不是已完成 peer-reviewed causal attribution。
Sec.7.3 pp.18-19 · Conclusion pp.20-21
ENGINEERING TAKEAWAYS

可直接帶走的三個設計原則

  1. Provenance first： world facts、agent experience、summary、opinion 應該有不同 type 與不同 update path。
  2. Retrieval is plural： semantic、keyword、graph、temporal 各自承擔不同 failure mode；fusion 比押一種 score 實際。
  3. Beliefs are state： 如果 agent 要有長期觀點，至少要讓 confidence、證據關係與 revision history 能被檢查。
Secs.3-6 pp.4-17
APPENDIX / ORIGINAL WORDING

原文精華：architecture 的定位

“HINDSIGHT is a memory architecture for AI agents that unifies long-term factual recall with preference-conditioned reasoning.”

HINDSIGHT 把長期事實回憶與受偏好條件約束的推理，放進同一個 agent memory architecture。

“Because it is rank-based, it does not rely on raw scores being calibrated across systems.”

RRF 以排名而不是未校準的原始分數融合多個 retrieval channel。
