Evolutionary Caching to Accelerate Your Off-the-Shelf Diffusion Model

把 Diffusion Transformer 的 feature cache 從手調規則，改成可選擇的 speed–quality Pareto frontier。

Anirud Aggarwal · Abhinav Shrivastava · Matthew Gwilliam
University of Maryland, College Park
ICLR 2026arXiv:2506.15682v3 · 2026-03-02
TL;DR

不是問「cache 幾次」，而是搜尋：
哪個 component、哪個 block、哪個 denoising step 可以不重算。

ECAD 以 NSGA-II 搜尋 per-model schedule，把不同 latency budget 對應成一條 frontier。
§1 pp.1–2 · §3.2 pp.5–6
THE COST

Diffusion 的品質來自反覆 denoise，也因此慢

  • 典型生成需 20–50 個 denoising steps；每步都穿過整個網路。
  • Training-free caching 重用前一 timestep 的 intermediate features，因此跳過部分計算、但不改權重。
  • 難點不在「能不能 cache」，而在 caching 變激進時，品質與可遷移性會一起掉。
工程上真正需要的是一組可選 operating points，而不是一個固定 heuristic。
§1 p.1 · §2.2 p.3
PRIOR METHODS

固定 cache rule 把 deployment choice 壓成幾個點

既有 heuristic

  • 固定 timestep interval / component 範圍。
  • 通常只能給少數 2x、3x 類的速度設定。
  • 跨 DiT architecture 常要重調。

ECAD 的改寫

  • 把每個 schedule 視為一個搜尋候選。
  • 同時評估 quality 與 cost。
  • 保留整條 Pareto frontier 給部署端選。
§1 pp.1–2 · §2.2 p.3
REFRAMING

cache schedule = multi-objective optimization
minS ( C(S), Q(S) )

C(S)：compute / MACs；Q(S)：generation quality。改善一側通常會傷另一側。
§3.2 p.5
REPRESENTATION

一張 binary tensor 指定每次「重算」或「重用」

S in {0,1}N x B x C
  • N = diffusion steps；B = transformer blocks；C = cacheable components。
  • S[n,b,c] = 0：使用 t+1 的 cached feature；更多 0 會降 compute，但可能傷品質。
  • 可分別處理 self-attention、cross-attention、feedforward，而非整個 block 一刀切。
§3.1 pp.4–5
METHOD FIGURE

Component-level caching + evolutionary search

搜尋粒度足夠細：不是只挑 block，也能挑每個 component 在每個 step 要不要重算。
Fig.2 p.3 · §3.1 p.4
ALGORITHM

ECAD 的一次 evolutionary loop

  1. Initialize：random 或 seed 一組 cache schedules。
  2. Evaluate：以 calibration prompts 生成影像，記 Image Reward 與 MACs。
  3. Select：NSGA-II 保留 non-dominated candidates。
  4. Breed：4-point crossover + bit-flip mutation，重複到指定 generations。
  5. Return：跨所有 generations 的 Pareto frontier。
Algorithm 1 p.4 · §3.2 pp.5–6
WHAT YOU CONFIGURE

它不是 black box；四個 knob 決定搜尋問題

  • Tensor shape：N / B / C 決定可 cache 的粒度。
  • Calibration prompts：paper 使用 100 Image Reward prompts。
  • Metrics：quality 用 Image Reward，cost 用 MACs。
  • Initial population：可 random，也可用 FORA 等既有 schedule 作 seed。
輸出是「特定 model + scheduler + step count」的 frontier，不是通用 cache rule。
§3.2 pp.5–6
THE OUTPUT

Frontier 讓 latency budget 成為第一級選擇

  • 部署端可以選 fast / faster / fastest，而不是接受單一作者預設。
  • 對同一 model，frontier 預期保留在 quality 與 latency 都不被其他候選支配的 schedules。
Fig.1 p.2 · §1 pp.1–2
EVALUATION

三個 DiT，兩個 resolution，品質與成本分開量

  • Models：PixArt-alpha、PixArt-Sigma、FLUX.1-dev；default sampler、20 steps。
  • Calibration：256x256；evaluation 同時做 256x256 / 1024x1024。
  • Quality：Image Reward、FID、CLIP ViT-B/32；sets：Image Reward, PartiPrompts, COCO2017-30K, MJHQ-30K。
  • Speed：MACs + 1 x NVIDIA A6000 的 end-to-end latency。

MECHANISM · CROWN PAGE

ECAD 的增益不是「cache 更多」，而是
把不可重算的地方留下，把可重用的地方找出來。

Search space = component x block x timestep；固定 interval 只是在這個 space 裡挑一小撮手寫點。
§3.1–§3.2 pp.4–6
CALIBRATION ABLATION

省 GPU 預算時，少 sample 不如少 prompt 危險

  • Population 72->24、每 prompt images 10->3、prompts 100->33，各自約省 66% GPU time。
  • 少 images / prompt 並不明顯有害。
  • 只留 33 prompts 則顯著傷害 frontier；作者認為關鍵是 set size，不是 diversity。
  • 100 個由 ChatGPT 產生的 prompts 在 appendix 中與 human-curated set 相近。
§4.4 p.9
PRACTICAL RECIPE

如果要把它放進 image serving pipeline

  1. 鎖定 model + sampler + steps + target resolution，不要把 schedule 當作完全通用。
  2. 準備大而足夠多的 calibration prompt set；paper 的 evidence 不支持只縮到 33 prompts。
  3. 先以 Image Reward / MACs 快速找 frontier，再把 selected points 用你的 downstream metric 抽驗。
  4. 將 fast / faster / fastest 映射到產品 SLO，而不是只挑 paper 最快點。
§3.2 pp.5–6 · §4.3–§4.4 pp.8–9
THE HIDDEN BILL

Training-free inference 不代表 search-free

550 generations72 schedules / gen1,000 imgs / candidate
  • PixArt-alpha main run 的候選評估規模很大：這是 offline optimization cost，不是 runtime cost。
  • 若 deployment 只跑一次或 model 頻繁變更，這筆 amortization 必須先算。
ECAD 改善的是「同一模型大量 serving 時」的 frontier，而非免費 shortcut。
§4.2 p.7
LIMITS

這篇有三個不能偷掉的前提

  • Metric alignment：fitness 綁 Image Reward；作者也承認 human ranking 可能更好。
  • Trade-off remains：更激進 schedule 在部分 metrics 仍會退化。
  • Target mismatch：256x256 schedule 能 transfer，但若 compute 允許，作者仍建議在目標 resolution 重優化。
§5 p.9 · Table 1 p.5 · §4.3 p.9
BOTTOM LINE

把 cache policy 視為可搜索的 Pareto object，
比把它寫成固定 heuristic 更符合部署現實。

最值得帶走的不是一組 bits，而是 component-level search + multi-objective frontier 這個介面。
