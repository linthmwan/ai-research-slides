Efficient Memory Management for Large Language Model Serving with PagedAttention

Woosuk Kwon*, Zhuohan Li*, Siyuan Zhuang, Ying Sheng, Lianmin Zheng, Cody Hao Yu, Joseph E. Gonzalez, Hao Zhang, Ion Stoica

vLLM 把 KV cache 變成像 OS page table 一樣可分頁、可共享、可 preempt 的 memory substrate。

SOSP '23arXiv 2309.06180v1GitHub Trending 2026-08-23
Cover / Abstract p.1; GitHub README links official paper
TL;DR

vLLM 的關鍵不是把 attention kernel 做得更快，而是讓 memory layout 不再決定 batchability。

PagedAttention 允許 logical KV cache 連續、physical memory 不連續；因此 request 可以動態 grow、跨 sample/beam 共享，最後在相同 latency 下拿到 2-4x throughput。

Abstract p.1 lines 12-31; Conclusion p.14 lines 1936-1947
Problem / why memory dominates

Autoregressive serving 的瓶頸在 KV cache，不在模型參數本身

  • generation phase token-by-token，matrix-vector dominant，GPU compute 常被低利用率卡住。
  • batching 可以攤平 model weights movement，但 batch size 先被 GPU memory capacity 限制。
  • OPT-13B 單 token KV cache 需要 800 KB；2048 tokens 時單 request 可到 1.6 GB。
  • A100 40GB 上，13B model parameters 約 26GB / 65%，KV cache 接近 30%。
800 KB / token1.6 GB / request~30% KV cache
§2.2 p.3 lines 314-328; §3 p.4 lines 414-424; Fig.1 p.1
Waste / contiguous allocation

既有系統把動態長度 request 塞進固定連續 chunk

  • 因為 tensor 要 contiguous，系統通常按 max sequence length upfront reserve。
  • waste 來自 reserved future slots、internal fragmentation、external fragmentation。
  • profiling 顯示有效 token states 只有 20.4%-38.2%；其餘 memory 仍阻止新 request 進 batch。
§1 p.2 lines 158-184; §3.1 p.4 lines 459-488; Fig.2 p.2
Design move

PagedAttention: 把 KV cache 切成固定大小 blocks

  • 每個 sequence 的 KV cache 被 partition 成 KV blocks。
  • 每 block 保存固定數量 token 的 keys / values。
  • kernel 逐 block fetch，而不是要求一整段 contiguous KV tensor。
  • 這把 OS paging 的 abstraction 搬到 attention operator 的 memory layout。
§4.1 p.5 lines 545-616
Formula / blockwise attention

公式只是換索引：attention over blocks 而不是 over one flat KV array

Aij = softmax(qiTKj / sqrt(d));   oi = sumj VjAijT
  • Kj, Vj 是第 j 個 KV block，不要求 adjacent blocks 在 physical memory 相鄰。
  • PagedAttention kernel 在計算時查 block table，分別讀取 physical blocks。
  • 模型數值語義不變；改的是 KV cache 的 addressing 與 allocation discipline。
用一層 indirection 換掉 contiguous allocation 假設。
Eq.(4) §4.1 p.5 lines 579-612
System overview

vLLM = centralized scheduler + KV cache manager + GPU workers

  • KV cache manager 維護 logical-to-physical mapping。
  • centralized scheduler 選 batch、分配 blocks、處理 preemption。
  • distributed GPU workers 共享同一份 mapping；各自只存對應 attention heads 的 KV slice。
§4 p.5 lines 524-542; §4.6 p.9 lines 1135-1205
Block table

Block table 讓 logical KV cache 連續、physical KV cache 不連續

  • prompt phase 只配置必要 blocks，不預留最大生成長度。
  • 最後一個 logical block 的 unfilled slots 才是主要 waste。
  • 當 block 滿了才 allocate 新 physical block；request 結束後 blocks 立即可釋放。
  • 因此每個 request 的 waste 被限制在 one block 內。
§4.2 p.5-6 lines 619-730; §4.3 p.6 lines 829-835
Mechanism crown

PagedAttention 用 kernel indirection 買回 batch size headroom。

微觀上 block table access 讓 attention kernel 慢 20%-26%；系統層卻因 KV memory 幾乎不浪費，能塞進更多 concurrent requests，end-to-end throughput 反而大幅提升。

+20%-26% kernel latency2-4x throughput
§7.1 p.12 lines 1750-1762; Abstract p.1 lines 25-29
Sharing / parallel sampling

同一 prompt 的多個 samples 不該複製 prompt KV cache

  • parallel sampling 中，一個 request 產生多個 outputs，但 prompt KV cache 相同。
  • 多個 logical blocks 可 map 到同一 physical block，physical block 帶 reference count。
  • 當其中一條 sequence 要寫共享 block，vLLM 做 block-level copy-on-write。
§4.4 p.7 lines 916-951
Sharing / beam search

Beam search 的分叉樹可以直接變成 block sharing graph

  • beam candidates 不只共享 prompt，也可能共享中間 blocks。
  • top-k 更新後，落選 candidates 的 logical blocks 被 free，physical block refcount 歸零就回收。
  • 既有系統常要大段 copy KV cache；vLLM 只在舊共享 block 被寫入時 copy one block。
§4.4 p.7 lines 982-1014
Shared prefix

System prompt / few-shot prefix 可以像 shared library 一樣常駐

  • 服務端可預先把 shared prefix 的 KV cache 放在 reserved physical blocks。
  • 每個 user prompt 的 logical blocks 直接 map 到這些 cached physical blocks。
  • last shared block 標記 copy-on-write；prompt phase 只需計算 task input。
§4.4 p.8 lines 1048-1061
Scheduling / preemption

Preemption 不是 evict 一個 page；而是 evict 一整個 sequence group

  1. FCFS fairness: earliest arrived requests served first，latest requests preempted first。
  2. all-or-nothing eviction: 因為一次處理 request 需要它所有 token states。
  3. gang scheduling: beam candidates / sequence group 可能共享 blocks，必須一起 preempt / reschedule。
  4. recovery 有 swapping 到 CPU RAM，或把 tokens 串回 prompt 後 recompute KV cache。
這不是照搬 OS paging；vLLM 把 LLM semantics 寫進 eviction policy。
§4.5 p.8 lines 1077-1133; Discussion p.13 lines 1868-1879
Implementation

要讓 block indirection 不拖垮 serving，kernel 要 fused

8.5K Python2K C++/CUDA3 fused kernels
  • control plane: scheduler / block manager in Python。
  • data plane: custom CUDA kernels for PagedAttention and block operations。
  • fused reshape + block write 減少 launch overhead。
  • fused block read + attention 讓 kernel 讀 block table 後直接做 attention。
  • fused block copy 批次處理 copy-on-write 的 discontinuous blocks。
§5 p.9 lines 1207-1217; §5.1 p.9 lines 1255-1276

Main result

Basic sampling: memory efficiency 轉成更高 sustainable request rate

  • ShareGPT: vLLM 比 Orca (Oracle) 可 sustain 1.7x-2.7x higher request rates。
  • 比 Orca (Max) 高 2.7x-8x；比 FasterTransformer up to 22x。

Complex decoding

decoding 越複雜，block sharing 的價值越明顯

  • parallel sampling: output sequence 越多，共享 prompt KV cache 的收益越大。
  • beam search: sharing pattern 更動態，vLLM over Orca (Oracle) 從 basic sampling 的 1.3x 升到 beam width 6 的 2.3x。
  • 這直接驗證 PagedAttention 不是只優化 greedy/sampling，而是支援 complex access patterns。

Shared prefix and chatbot

長 system prompt / few-shot prompt 正是 PagedAttention 的甜點區

Ablation / block size

block size = GPU parallelism vs fragmentation / sharing 的 knob

  • too small: PagedAttention 讀取 KV cache 時 GPU parallelism 不足。
  • too large: internal fragmentation 增加，sharing probability 下降。
  • ShareGPT: block sizes 16-128 lead to best performance。
  • Alpaca: 16 / 32 work well；larger block sizes degrade because sequences are short。
  • vLLM default block size = 16。
vLLM 的 page size 不是美學設定，是 workload-dependent systems knob。
§7.2 p.12 lines 1764-1781; Fig.18b p.12
Ablation / recovery

Preempted KV cache 要 swap 還是 recompute，取決於 block granularity

  • small block sizes: swapping 造成大量 small CPU-GPU transfers，effective PCIe bandwidth 低。
  • recompute 不使用 KV blocks，overhead across block sizes 基本固定。
  • medium block sizes 16-64: swapping / recomputation end-to-end performance comparable。
§7.3 p.13 lines 1831-1847
Limits

這個 OS analogy 有邊界：不是所有 GPU workload 都該 paging

  • DNN training: tensor shapes 通常 static，可 ahead-of-time optimize allocation。
  • non-LLM serving: 若 workload compute-bound，memory efficiency 不一定轉成 throughput。
  • PagedAttention 有 real indirection overhead；若 memory 不是瓶頸，可能反而 degrade。
  • Orca baseline 是作者 reimplementation；Orca (Oracle) 是 infeasible upper bound。
適用條件很窄也很重要：dynamic unknown sequence lengths + GPU-memory-capacity-bound serving。
Discussion p.13 lines 1849-1867; §6.1 p.10 lines 1446-1456
Engineering read

vLLM 的持久價值，是把 LLM serving 問題重寫成 memory management 問題。

如果一個系統的 effective batch size 被 dynamic state memory 卡住，先問 allocation / sharing / recovery，再問 kernel 是否已經極致。這篇就是那個順序的範例。
