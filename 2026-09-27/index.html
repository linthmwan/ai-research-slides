Hindsight is 20/20

Building Agent Memory that Retains, Recalls, and Reflects

A structured memory substrate for long-lived agents — not another top-k retrieval wrapper.

arXiv technical report14 Dec 2025
Latimer, Boschi, Neeser, Bartholomew, Srivastava, Wang, Ramakrishnan et al.
Vectorize.io · The Washington Post · Virginia Tech
Source: arXiv:2512.12818v1 · cover p.1 · trending repo: github.com/vectorize-io/hindsight
TL;DR

Memory becomes four kinds of state plus three explicit operations: retain · recall · reflect.

The design separates evidence, experiences, neutral summaries, and subjective beliefs instead of flattening all of them into retrieval chunks.
Abstract p.1 · §3 pp.4-5
PROBLEM

Why a long context is not a memory system

  • Top-k RAG keeps the model itself stateless; it retrieves snippets but does not maintain an explicit account of what was observed versus what is believed.
  • Long-lived agents need cross-session recall, temporal and causal access, traceable updates, and stable behavioral preferences.
  • The claimed failure is context dilution: raw conversation history is present, yet the relevant relation is hard to surface reliably.
The paper attacks memory organization and retrieval semantics, not merely context-window length.
Abstract p.1 · §1 p.2
DESIGN TARGET

Four networks give information an epistemic type

Evidence side

  • World (W): objective external facts.
  • Experience (B): first-person agent actions and history.
  • Observation (S): preference-neutral entity summaries synthesized from facts.

Belief side

  • Opinion (O): subjective judgment + confidence + formation time.
  • The graph connects memory units with temporal, semantic, entity, and causal links.
  • Explicit typing makes provenance and later revisions inspectable.
§3.1 pp.4-5 · Fig.1 p.4
CONTRIBUTIONS

The architecture is a stack, not a single retrieval trick

  1. Four-network memory bank separates facts, personal experiences, summaries, and opinions.
  2. TEMPR extracts temporal narrative facts and performs agent-oriented recall.
  3. CARA makes reflection profile-conditioned and allows opinions to evolve.
  4. End-to-end evaluation targets long-horizon conversational benchmarks.
§1 p.2 · §3 pp.4-5
SYSTEM MAP

Input -> temporal memory bank -> retrieved evidence -> reflection

The architecture routes the same memory bank through both factual retrieval and belief update.
Fig.2 p.5 · §3.2-3.3 pp.4-5
RETAIN

Store a self-contained narrative fact, not a pile of utterances

Memory unit

fact = text + embedding + time range + type + metadata
  • Each fact belongs to exactly one network.
  • Temporal occurrence and mention time support historical queries and recency-aware ranking.
  • Opinion nodes additionally carry confidence.

Extraction policy

  • The extractor creates 2-5 comprehensive facts per conversation.
  • It resolves coreference, normalizes time expressions, attributes participants, preserves stated reasons, classifies type, and extracts entities.
  • A narrative fact preserves cross-turn context that sentence chunks lose.
§4.1.1 pp.6-7 · §4.1.2 pp.7-8 · Fig.3 p.7
RETAIN

Canonical entities turn distant mentions into graph neighbors

  • Entity resolution combines string/name similarity, entity co-occurrence, and temporal proximity.
  • Any two facts mentioning the same canonical entity receive a bidirectional entity link.
  • Temporal links favor nearby events; semantic links pass a similarity threshold; LLM-extracted causal links are upweighted for explanatory traversal.
edge types = temporal | semantic | entity | causal
§4.1.3-4.1.4 p.8
RETAIN

Observations are a cache of neutral entity profiles

  • For “tell me about Alice,” retrieving all raw facts is redundant; an observation summarizes salient properties for that entity.
  • Observations are preference-neutral and have no confidence score; opinions are subjective, profile-shaped, and confidence-scored.
  • When new facts arrive, an asynchronous job regenerates the entity observation without blocking writes.
observation(entity) = SummarizeLLM(all facts mentioning entity)
§4.1.5 p.9
RECALL

Do not choose between lexical, semantic, graph, and time retrieval.
Run all four, then let them vote.

TEMPR exposes a token budget rather than a fixed top-k: simple questions request less context; complex multi-hop questions can expand retrieval.
§4.2-4.2.2 pp.9-10
RECALL

Four channels cover four meanings of “relevant”

Direct matches

  • Semantic: vector similarity catches paraphrases and conceptual matches.
  • BM25 keyword: protects proper nouns, API names, and identifiers.

Structural matches

  • Graph spreading activation: follows entity, time, semantic, and causal links from semantic seeds.
  • Temporal graph retrieval: normalizes query time ranges and restricts traversal to matching events.
§4.2.2 pp.9-10
RECALL

Fuse ranks, rerank candidates, then pack the token budget

RRF(f) = sum over channels of 1 / (60 + rank(channel, f))
  • Rank fusion avoids assuming semantic, lexical, graph, and temporal scores share a calibrated scale.
  • A cross-encoder jointly reads query and candidate to improve final precision.
  • Greedy budget filtering returns ordered facts until their total token count would exceed the requested budget.
Agreement across independent retrieval routes becomes evidence; a missing route is not a penalty.
§4.2.3-4.2.5 p.11
REFLECT

CARA makes the reasoning style an explicit bank parameter

Fig.4 p.13 · §5 pp.11-13
REFLECT

A compact profile controls how strongly beliefs shape language

Profile axes

  • Skepticism: 1 trusting -> 5 skeptical
  • Literalism: 1 flexible -> 5 literal
  • Empathy: 1 detached -> 5 empathetic
  • Bias strength: beta in [0,1]

Operational meaning

  • The numeric profile is verbalized into a system-message description.
  • beta = 0 prioritizes fact-based reasoning; beta = 1 strongly encourages profile-consistent opinions.
  • The paper uses neutral S=L=E=3 and beta=0.2 in factual benchmark runs.
§5.2.1 p.12 · §5.3.1 p.13 · §7.3 p.18
REFLECT

Opinion formation is a structured write-back path

  1. Recall relevant world facts, experiences, and prior opinions for the query.
  2. Load name, concise background, and the verbalized behavioral profile.
  3. Generate an answer plus candidate opinion updates.
  4. Parse structured output and store new or updated opinions with confidence and entity references.
opinion = statement + confidence + timestamp + bank + entities
§5.4.1-5.4.2 p.13
REFLECT

Opinions change gradually rather than being overwritten

  • A new fact finds candidate opinions through entity overlap or embedding similarity.
  • The system classifies the relationship as reinforce, weaken, contradict, or neutral.
  • Confidence increases by alpha for reinforcement, decreases by alpha for weakening, and by 2 alpha for contradiction; strong contradictions may also revise text.
confidence update: +alpha | -alpha | -2alpha | unchanged
The proposed safeguard is trajectory stability: isolated evidence should not cause belief oscillation.
§5.5 pp.14-15
UNIFIED LOOP

Retain, recall, reflect form a closed memory lifecycle

Write path

  • Extract narrative facts with time and entities.
  • Build graph links, update observations, reinforce related opinions, and merge background.

Read + reason path

  • Run four retrieval routes, fuse ranks, rerank, and fit the token budget.
  • Generate an answer conditioned on retrieved facts and profile; store resulting opinion updates.

EVALUATION

Protocol isolates memory architecture from a small backbone

  • Retention and reflection use GPT-OSS-20B; the judge is GPT-OSS-120B at temperature 0.0.
  • Each test query runs four-way retrieval + RRF + reranking, then CARA generates the response.
  • Factual benchmarks use a neutral profile: skepticism = literalism = empathy = 3, beta = 0.2.
The cleanest comparison is OSS-20B full context versus OSS-20B with Hindsight: same backbone, different memory layer.

ENGINEERING READING

What is reusable even if the headline numbers move

  1. Type memory by epistemic role: do not let raw evidence, summaries, and user-facing beliefs share one indistinguishable store.
  2. Retrieve with complementary failure modes: exact identifiers, paraphrases, graph relations, and time constraints demand different indexes.
  3. Make revision explicit: record confidence and evidence-triggered update rules instead of silently rewriting all prior state.
  4. Expose a budgeted interface: “how much context is worth it?” belongs in the memory API.
§3-6 pp.4-17 · interpretation grounded in the described architecture
LIMITS / READING CAUTION

The report is promising, but its evidence has boundaries

  • This is an arXiv technical report, not a stated peer-reviewed acceptance.
  • Several comparator scores are carried over from a Supermemory report or official Backboard results; the authors say these are reported reference points, not independently reproduced baselines.
  • The experimental setup leaves literal `` placeholders for retrieval token budgets, so the exact budgets are not disclosed in this version.
  • The factual benchmarks use neutral profiles; they do not measure whether preference-conditioned personas are safe, useful, or stable for users.

APPENDIX · PAPER HIGHLIGHT

Why four retrieval routes?

“Running these four channels in parallel yields a diverse set of candidates.”

四個通道的目的不是重複搜尋，而是從語意、字面、圖結構與時間四種相關性產生候選。§4.2.2 p.10

  • Semantic handles paraphrases.
  • BM25 preserves exact names.
  • Graph traversal reaches indirect relations.
  • Temporal filtering answers “when?” as a first-class constraint.
