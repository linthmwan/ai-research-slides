FixAnything: 3D-Consistent Rendering Refinement via Video Generative Priors

Khiem Vuong · Deva Ramanan · Srinivasa Narasimhan · Carnegie Mellon University
ECCV 2026arXiv:2608.23549Announced 2026-08-24

Single video prior + LoRA + mask + geometry-aware DPO for cleaning renderings from NeRF, 3DGS, mesh, and sparse point clouds.

Source: arXiv:2608.23549 · project page on paper cover p.1
TL;DR

把 rendering cleanup 當成 video-to-video translation，而不是替每種 3D representation 重做一套 specialist pipeline。

Renderer supplies camera path and coarse structure; pretrained video model supplies natural-video completion; mask and Flow-DPO keep it anchored and 3D-consistent.

Abstract pp.1-2; §1 pp.2-3
Problem

Sparse-view / far-view artifacts look different, but fail for the same reason

  • 3DGS: floaters; NeRF: fog / blur; mesh: holes; sparse points: scattered patches.
  • All four still expose a camera trajectory and rough scene layout; all deviate from the manifold of natural videos.
  • The paper asks whether one generalist video prior can replace a growing family of representation-specific cleanup systems.
§1 p.2; §3.1 pp.5-7
Prior work trap

Generative priors help, but most systems specialize too hard

Sparse-view reconstruction
  • RegNeRF / FreeNeRF / DNGaussian / FSGS regularize geometry, but stay constrained by weak observations.
  • They reduce artifacts without truly hallucinating plausible missing content.
Post-hoc enhancement
  • 3DGS-Enhancer, Xu et al., Difix3D/Difix3D+ use generative priors.
  • But many process views independently or in small sets; cross-view consistency is left to the 3D representation.
The gap: a representation-agnostic cleanup model that processes the full rendering video at once.
§2 pp.4-5; §4.2 p.11; Fig.7 p.13
Core formulation

Any renderer becomes a structural scaffold

input video x in RT x 3 x H x W, mask m in {0,1}T -> clean video y = cleanup(x,m)
  • m_i = 1 means the frame is clean / near a training viewpoint; m_i = 0 means it needs fixing.
  • The output should preserve scene content and camera motion while repairing degraded frames.
  • This is representation-agnostic because the model only requires rendered video + clean-frame mask, not renderer internals.
§3.1 pp.5-7
Architecture

Minimal changes: concatenate conditioning latents, train LoRA only

Base Wan2.1-I2V-14B and VAE stay frozen; LoRA rank 64 updates <1% of parameters.
§3.2 pp.5-8
Latent conditioning

The model sees noisy target latent + degraded rendering latent + trust/fix mask

z_t = (1-t) z_0 + t epsilon
z_hat_t = [ z_t ; z_cond ; m ]
L_FM = E || v - v_theta(z_hat_t,t) ||2
  • z_cond = E(x) carries camera trajectory and coarse scene layout.
  • m is spatially broadcast and concatenated channel-wise.
  • Velocity target: v = epsilon - z_0; training follows rectified-flow matching.

Formula is simplified into HTML-safe notation; no MathJax dependency in this deck renderer.

Training data

DL3DV-10K trajectories teach conditioning, not video generation from scratch

  1. Sample k in [3,12] training frames per scene, then extract 61-frame trajectories passing through at least two clean views.
  2. Render each trajectory as NeRF, underfit 3DGS (7K iterations), MapAnything mesh, and sparse COLMAP keypoints.
  3. Replace training-view frames with original images for mesh / sparse-point inputs to provide dense clean anchors.
  4. SFT: 500 paired videos, 288x512 then 480x832, 3000 iterations on one H100; DPO adds 2000 iterations.
§3.3 pp.8-9; §4.1 p.11
Geometry-aware preference optimization

Reward the videos that downstream SfM can reconstruct

  • For 1,000 separate scenes, sample five outputs with different seeds.
  • Rank candidates using COLMAP + SuperPoint + LightGlue pose recovery; metric is RRA/RTA AUC@5.
  • Keep preference pairs with AUC gap >= 0.2 and train Flow-DPO against the SFT reference checkpoint.
§3.4 pp.9-10; §4.3 p.12
Mechanism crown

Image realism is not enough. FixAnything optimizes for whether geometry can be recovered from the generated video.

That is the paper’s most important move: use SfM pose accuracy as a preference signal, then bake it into LoRA so inference stays unchanged.

AUC@5: 61.12 -> 68.32+7.20 extra inference cost
Tab.2 p.12; §3.4 pp.9-10
Inference

Default 50 steps, but the speed-quality curve is unusually forgiving

  • Sampling starts from Gaussian noise at t=1 and integrates toward t=0 using `[z_t ; z_cond ; m]`.
  • Default is 50 denoising steps; long videos use overlapping 61-frame chunks.
  • Ablation shows 5 steps can generate a 61-frame 480x832 clip in 31s on one H100, versus 309s at 50 steps.
§3.5 p.10; Tab.5 p.14
Experiment setup

DL3DV sparse-view evaluation with image and geometry metrics

Data / protocol
  • 20 held-out DL3DV-10K scenes.
  • 3, 6, or 9 uniformly selected training frames.
  • Remaining non-training frames sampled every 8th frame as query set.
Metrics / baselines
  • PSNR, SSIM, LPIPS for image quality.
  • RRA/RTA AUC@5 for geometric consistency.
  • Baselines: 3DGS, RegNeRF, FreeNeRF, DNGaussian, FSGS, 3DGS-Enhancer, Xu et al., Difix3D/Difix3D+.

Qualitative comparison

Sharpening each frame independently can amplify cross-view inconsistency

  • This is exactly where video priors matter: full-sequence cleanup gives temporal context.
  • The claim is not just prettier frames; it is fewer view-to-view contradictions.

Interpretation

The paper quietly demotes 3D representations from “final answer” to “conditioning scaffold”.

If sparse SfM points + clean anchors can match 3DGS after generative cleanup, the expensive dense representation may not always be the central object.

§1 p.3; §4.2 p.11; §6 p.15
Limits

Strong result, but not a solved deployment story

  • Hallucination remains: useful completion becomes failure when it contradicts observed content.
  • Uncertainty is preliminary: five stochastic runs and per-pixel std are not a calibrated safety guarantee.
  • Compute remains real: Wan2.1-I2V-14B, H100 training, and 31s even at 5 steps for a 61-frame clip.
  • Temporal window: long videos are chunked into overlapping 61-frame windows; very long-horizon consistency is not fully established.
  • Main tables center on DL3DV; MipNeRF-360 / LLFF are mentioned as supplementary results in the extracted main text.
§3.5 p.10; §4.1 p.11; §5 p.14; §6 p.15
Engineering read

What an image/video engineer should steal from this

  1. Use existing renderers to expose motion / layout, then let the video model do perceptual completion.
  2. Do not let generative cleanup overwrite known-good frames; pass an explicit trust mask.
  3. Optimize for downstream reconstructability, not only PSNR / LPIPS.
  4. Keep adaptation disposable: LoRA on top of new video backbones should be cheaper than redesigning a custom 3D architecture.
  5. Report uncertainty maps when you hallucinate content; users need to know which pixels are guesses.
