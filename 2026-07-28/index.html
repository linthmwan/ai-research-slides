LLM2CLIP: 用 LLM 重塑 CLIP 的文字端

Weiquan Huang*, Aoqi Wu*, Yifan Yang†‡, Xufang Luo, Yuqing Yang, Usman Naseem, Chunyu Wang, Qi Dai, Xiyang Dai, Dongdong Chen, Chong Luo, Lili Qiu, Liang Hu

來源: cover p.1 lines 3-10, 52-53; arXiv v6 25 Feb 2026
TL;DR

不是「把 LLM 塞進 CLIP」就會變強。

LLM2CLIP 先把 LLM 變成 caption-contrastive embedding model，再凍結 LLM、用小 adaptor 接到 CLIP vision encoder，讓 dense caption 的語義進到 shared space。

Problem / Why now

CLIP 已經是多模態系統的地基，但文字端開始拖後腿

  • CLIP 的 dual-tower embedding 支撐 retrieval、detection、segmentation，也被 Stable Diffusion / Wan / LLaVA 這類系統當作 text / visual backbone。
  • 原始 CLIP text encoder 對 長句、密集 caption、open-world knowledge 的處理能力不足，這正是現代圖像理解與生成 prompt 的痛點。
  • 長 caption CLIP work 常靠 summarization、segmentation 或 positional encoding 補丁；LLM2CLIP 問的是：能不能直接把 LLM 的語義能力遷進 CLIP？
Introduction p.1-2 lines 37-47, 90-131; Related Works p.2-3 lines 236-250
The trap

直接拿 raw LLM embedding 做 CLIP contrastive training 會失敗

障礙 1: separability

  • LLM embedding 原本是為 next-token / text tasks 形成，不自然適合 image-caption contrastive matching。
  • COCO caption-to-caption top-1 範例顯示 raw LLaMA retrieval 會拿到語義不相干的句子。

障礙 2: cost

  • CLIP pretraining 已經昂貴；把 LLM 一起端到端訓練，GPU memory 與時間都不可接受。
  • 所以方案必須讓 LLM 的能力進來，但不要讓 LLM 的訓練成本進來。
Introduction p.2 lines 132-154; Figure 2 p.2 lines 193-215

Stage 1 / Caption embeddingization

把 LLM 從 generator 改造成 caption embedding model

  • Average pooling 取代只用 EOS token，實驗上更適合句子表徵。
  • Bidirectional attention：encoder-focused 場景不需要 causal generation mask。
  • LoRA：用 PEFT 啟動輸出特徵的文字理解能力，不做全量訓練。
  • Supervised SimCSE：同一張圖的兩個 caption 作正樣本，讓 caption space 變得可分。

Stage 2 / CLIP post-finetuning

凍結 LLM，訓練 vision encoder + 小 adaptor

What changes

  1. 移除原本 CLIP text encoder。
  2. 用 CC-finetuned LLM 輸出 sentence embedding。
  3. LLM 後接四層 linear adaptor/projector。
  4. 開 ViT gradients，做 cross-modal contrastive learning。

Why cheap

  • LLM gradients 全部 frozen。
  • 文字特徵可 offline precompute；訓練時不用把 LLM 放進 GPU memory。
  • 成本接近標準 CLIP fine-tuning，而不是重做 CLIP pretraining。
Methods §3.2 p.4-5 lines 821-849; Experiments §4.1 p.5 lines 877-888
Integration choice

主線不是融合兩個 text encoder，而是直接替換 CLIP-T

  • 作者測過四種選項：只用 LLM、CLIP-T/LLM 雙 loss、額外 CLIP-T↔LLM alignment、以及 concat feature。
  • 雙 loss 與顯式 alignment 幾乎沒有意義；concat 有提升但複雜，作者留作 future work。
  • 這讓 pipeline 乾淨：CL(LLM, CLIP-V) 是主目標，不再讓舊 CLIP-T 約束新 space。
Methods §3.2 p.5 lines 837-849; Table 9 p.7 lines 1353-1404; §4.4 p.7 lines 1416-1427

As MLLM visual encoder

把 LLM2CLIP 接回 LLaVA-1.5：它也像更好的 visual tokenizer

  • 作者沿用 LLaVA-1.5：CLIP-ViT-L-336 + MLP head + Vicuna-7B。
  • pretraining 558K image-caption pairs，instruction tuning 665K visual instruction samples。
  • +LLM2CLIP 在超過 87.5% benchmarks 上提升，只有兩項小幅下降。
  • 這支持一個工程解讀：dense caption 對齊不只改善 retrieval，也改善 vision encoder 作為 MLLM token source 的能力。
§4.2 p.6 lines 1181-1192; Table 5 p.6 lines 1053-1124

Trade-off

同一個方法：retrieval 大幅提升，ImageNet zero-shot 反而可能小跌

What improves

  • linear probe 變好：CLIP L/14-336 84.8 → 85.2，CLIP L/14 83.9 → 84.4。
  • segmentation / detection 也提升，說明 visual feature 不是只過度適配 text retrieval。

What regresses

  • ImageNet zero-shot 有小幅下降；作者認為 shared-space prompt alignment 對細粒度 class nouns 更脆弱。
  • 更多 finetuning data 可能緩解，但論文沒有驗證。
Table 3 p.5 lines 980-1003; §4.2 p.6 lines 1143-1166
Limitations

值得保留的三個保留意見

  1. Zero-shot classification alignment：ImageNet zero-shot 可下降，prompt/class-name space 不是免費改善。
  2. Data scale question：作者推測更多 LLM2CLIP finetuning data 可補救，但這仍是未驗證命題。
  3. Concat variant：Table 9 的 concatenation 更強，但因複雜度未納入 default；工程上可能值得重跑。
§4.2 p.6 lines 1143-1156; §4.4 p.7 lines 1424-1427
Engineering read

對 image / generative pipeline 的啟發

  • 如果 pipeline 依賴 CLIP text/image features，不一定要重訓整個 foundation model；可以用 dense caption + LLM text side 做低成本 post-finetuning。
  • 對 text-to-image / text-to-video：prompt text encoder 的長上下文理解與 open-world knowledge，可能比單純擴資料更直接改善 dense prompt grounding。
  • 但 deployment 要分清 retrieval / dense grounding 與 zero-shot class prompt；這兩個目標可能拉扯。
  • 最該重現的 ablation：raw LLM vs CC-finetuned LLM，這是整篇的因果關鍵。
