Benefits and Limitations of Communication in Multi-Agent Reasoning

A theory-first map of when extra agents reduce critical-path depth — and when they only add messages.

Michael Rizvi-Martel · Satwik Bhattamishra · Neil Rathi · Guillaume Rabusseau · Michael Hahn
ICLR 2026 PosterarXiv:2510.13903v2
ICLR 2026 Poster · arXiv v2 dated 2026-07-14 · selected for Saturday agent-systems rotation
THE PAPER IN ONE SENTENCE

More agents do not make reasoning cheaper. They help only when a task has parallelizable local work and communication can combine it.

The contribution is a resource calculus: total work, wall-clock depth, workers, and messages.
Abstract p.1; §4.1 pp.5-6
THE MOTIVATION

Long contexts create a tempting but underspecified workaround

  • CoT quality degrades as problem complexity and context length rise.
  • Applied multi-agent systems split documents, web pages, or RAG shards, then ask a manager to aggregate.
  • The missing question: which tasks benefit algorithmically from partitioning and which merely move the bottleneck?
§1 pp.1-2; §3.1 p.5
FOUR COST AXES

The system is a communication graph, not a bag of prompts

Graph model
  • Node Ti(t) = agent i at timestep t.
  • Edges either emit CoT tokens or send/broadcast a message.
  • Each worker receives a disjoint local input chunk.
Costs
  • Depth: longest path, a wall-clock proxy.
  • Width: number of agents w.
  • Size: total graph nodes / total work.
  • Communication budget: outgoing message events.
Definitions 3.1-3.2 p.3
FORMALIZATION

What each worker actually sees

local context = input chunk (N / w) + agent ID + received/emitted tokens + EOS
  • A Transformer implements the protocol only if every local string fits its context and the model can generate every outgoing token.
  • The main analysis uses a decoder-only unique hard-attention Transformer abstraction; bounded heads and layers are assumed across input lengths.
  • Single-token messages simplify notation; the authors state bounded-length words preserve the results.
Definition 3.3 p.4; §2 p.2
THE THREE REGIMES

Communication and depth do not have one universal tradeoff

TaskDepthCommunicationEngineering meaning
Associative recallO(1)O(1)Scale context without added critical path
State trackingO(N/w + log w)Theta(w)Spend messages for parallelism
k-hop reasoningO(k)Theta(k)Serial dependency survives partitioning
The task structure — not the number of agents — decides the regime.
Table 1 p.2; §§4.2-4.4 pp.6-7
A HARD CONSTRAINT

Parallelism cannot erase total work

Size(N) / w(N) <= Depth(N)
  • Any multi-agent protocol has an equivalent single-agent simulation with the same size up to a constant factor.
  • So agents can reduce elapsed depth by distributing work, but do not asymptotically reduce total computation.
  • If communication stays O(1) for every width, a single-agent CoT already solves the task at O(1) depth.
Propositions 4.1-4.2 and Eq. 2 p.5
MECHANISM · THE IMPOSSIBLE QUADRANT

Constant communication + decreasing depth is not a fourth regime. If messages never grow, parallel agents cannot create an asymptotic speedup.

This rules out a common intuition: “just add workers, but keep coordination negligible.”
Proposition 4.2; Figure 2 pp.5-6
REGIME 1 · ASSOCIATIVE RECALL

One worker finds the key; one message is enough

Figure 1(a) p.4
  • Workers receive key-value chunks and the query.
  • Attention identifies the matching pair locally.
  • Only the unique successful worker reports the value to the manager.
Depth O(1)Comm O(1)Size O(w)
Proposition 4.3 p.6
RECALL · EMPIRICAL CHECK

Divide-and-conquer stabilizes the long-context retrieval task

  • The baseline is self-consistency with majority voting; CoA implements the theory-aligned protocol.
  • Majority Voting also has trouble when the needle is near the beginning or end.
  • The result supports partitioning for retrieval, not a claim that every task benefits.
§5.1 pp.8-9; Figure 3 p.8
REGIME 2 · STATE TRACKING

Associativity lets workers form a parallel prefix-sum tree

Figure 1(b) p.4
  • A finite-monoid sequence represents state updates: e.g., PARITY, code execution, entity tracking, chess moves.
  • Workers summarize local chunks; tree merges compose those summaries.
  • With w=N, prefix sum achieves O(log N) depth.
§4.3 p.6; Proposition 4.5 p.6
STATE TRACKING · BOUND

The speedup has a price tag

QuantityAchievable boundLower-bound reading
DepthO(log w + N/w)Omega(N/w), up to log factor
CommunicationO(w)Omega(w) for nontrivial groups
Total sizeO(N)Omega(N) for PARITY
Near-linear parallel depth reduction demands near-linear communication; no free speedup is hiding in the protocol.
Propositions 4.4, 4.6-4.7 pp.6-7
STATE TRACKING · EMPIRICAL CHECK

Prefix Sum is the predicted protocol — and wins as sequences grow

  • Prefix Sum consistently beats other methods as sequence length grows.
  • Observed communication/depth behavior follows the N/w versus w prediction.
  • At high communication, extra constant depth comes from instruction-following overhead such as repeating the query.
§5.2 p.9; Figure 4 pp.8-9
MECHANISM · DESIGN RULE

Use a tree or cascade when partial results are associatively composable. The manager should not have to re-absorb every raw worker answer.

The authors explicitly propose prefix-sum-style iterative summarization to avoid shifting the entire context bottleneck to one manager.
§6 p.10
REGIME 3 · K-HOP REASONING

A lookup chain remains a chain

Figure 1(c) p.4
  • Each fact worker holds a partition; the query composes k functions.
  • The current answer determines the next lookup.
  • When consecutive facts are on different workers, an iterative message sequence is unavoidable.
§4.4 p.7
K-HOP · LIMIT

More workers do not shorten the serial dependency

Depth = O(k) · Communication = O(k) · Size = O(wk)
  • Communication is optimal; depth is optimal up to a log(N + k) factor.
  • In the worst case, relevant facts are distributed across workers, forcing one round per hop.
  • This is the counterexample to “multi-agent collaboration always means parallel reasoning.”
Proposition 4.8 p.7
K-HOP · EMPIRICAL CHECK

Iterative Query pulls ahead as the relation chain gets harder

  • The authors compare Majority Voting with the optimal Iterative Query protocol.
  • The advantage grows with difficulty; at the smallest tested hop count (four), Majority Voting sometimes wins.
  • Measured computation depth rises with hop count, matching theory.
§5.3 p.9; Figure 5 p.9
AGAINST NAIVE SELF-CONSISTENCY

Voting can need exponentially more agents on stateful tasks

Majority Vote: w(N) = 2^(Omega(N^c)) for O(log N) CoT depth · PrefixSum: w=N, O(log N) depth, perfect PARITY accuracy
  • The contrast is formal, not merely a plot: polynomially many voters cannot match the structured protocol under the stated constraint.
  • The lesson is to design the communication algorithm, not simply sample more independent answers.
Proposition 6.1 p.10
PRACTICAL PROTOCOL CHOICE

Classify the dependency before choosing an agent topology

  1. Local retrieval? Shard context and use sparse winner-to-manager reporting.
  2. Associative state update? Build a prefix tree; tune the width/communication tradeoff.
  3. Sequential lookup chain? Budget for iterative coordination; workers cannot erase k-step depth.
  4. Manager overload? Aggregate summaries hierarchically instead of dumping all outputs into one context.
§§4.2-4.4 pp.6-7; §6 p.10
WHAT THE PAPER DOES NOT CLAIM

Sharp theory, deliberately bounded scope

  • The formal model is a unique hard-attention Transformer abstraction, not every production LLM or agent runtime.
  • Main experiments are controlled synthetic tasks with hard-coded communication protocols.
  • The authors name graph reachability, adversarial games, cooperative RL, and alternative agent paradigms as extensions.
§2 p.2; §5 pp.7-9; §6 p.10

APPENDIX · PAPER HIGHLIGHT

The thesis in the authors’ own words

“The size of the protocol cannot be reduced using multiple agents beyond a constant factor.”

多代理不能把協定的總計算量降到常數因子之外；它改的是平行排程，而不是免費少做工作。§4.1 p.5

“Depending on how the facts are distributed among the agents, computation depth and communication budget may be Ω(k) in the worst case.”

若答案鏈跨 worker 分散，k-hop 的序列相依不能靠增加代理人數消失。§4.4 p.7

Quoted passages: §§4.1, 4.4 pp.5, 7

Communication is a resource, not a magic trick.

For agent systems: map the dependency graph first, then allocate workers and messages.
