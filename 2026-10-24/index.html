WALT: Web Agents that Learn Tools

把網站已經設計好的功能，轉成可驗證的高階工具；瀏覽器 agent 不必每次都從 click / type 開始推理。

THE THESIS

不要讓 agent 「學會點擊」；讓它呼叫網站本來就具備的功能。

WALT 的單位不是 replayable UI trace，而是帶 schema、測試與失敗回饋的 callable tool。
Abstract; §1 pp.1–2
01 · PROBLEM

web agent 的脆弱點在低階互動，而不是任務意圖

  • 同一個「找最便宜藍色 kayak」任務，UI policy 得處理搜尋框、下拉選單、hover、排序與 timing。
  • layout change、動態元素與長 horizon 會把每個 primitive action 都變成額外失敗機會。
  • 既有 skill discovery 多半從成功軌跡挖 action subsequence，或讓 agent 猜「有用技能」；仍然是易碎 UI script。
真正要抽象掉的是 how，把 planner 留在 what。
§1–2 pp.1–3
01 · BEFORE / AFTER

從 8+ 個介面步驟，縮成一個語意操作

傳統 browser agent

  • 定位 search box
  • 輸入 query
  • 找 category
  • 點 filter
  • 選 sort
  • 掃描結果與修正

WALT tool

search(query="blue kayak", category="Boats", sort_by="price")
  • schema 約束輸入
  • executor 封裝細節
  • 失敗時保留受控 fallback
Fig.1 + §1 p.1
01 · VISUAL INTUITION

工具化把 UI mechanics 移到可重用的實作層

planner 的工作變成選 tool 與組合 tool，不是反覆重新發明操作序列。
Fig.1 p.1
02 · CONTRIBUTIONS

四件事，讓「tool」有工程上的重量

  1. 網站功能 ≠ agent skill：從 site-provided capability 出發。
  2. 兩階段產線：discovery → construction / validation。
  3. determinism-first：穩定 selector、URL promotion、schema contract。
  4. 實證：VisualWebArena 52.9%、WebArena 50.1% 平均成功率。
§1; §3; §4.5 pp.1–8
03 · PIPELINE

先探索網站，再把候選功能做成可驗證的工具

關鍵不是一次把 trace 寫成 script；而是以 test input 把 tool 納入「可接受 / 退回修正」的閉環。
Fig.2; §3.1–3.2 p.4
03 · FORMULATION

工具是擴充 action space 的原子操作

A = Aprim ∪ Atools   ·   u: S → Goal
  • Aprim: click, type, navigate 等底層 action。
  • u: 接收結構化 schema S，完成明確目標，驗證後才註冊。
  • 這使 policy 能保留原始操作能力，同時把反覆出現的網站功能升成可選 action。
§3.1 p.3
03 · OBJECTIVE

最佳化的不是只有成功率

minimize   FailRate(u, Itest) + StepCount(u) + AgenticRatio(u)

可靠性與效率

  • 固定測試集上的失敗率
  • primitive operations 的步數

可控的 LLM 依賴

  • AgenticRatio 計入需要推理的步驟
  • 優先 URL / DOM deterministic operation
把「少用 agentic step」寫進目標，才能避免 tool 只是換名字的 agent loop。
§3.2 p.4
03 · STAGE 1

Tool discovery：找的是 user-facing intent 的覆蓋面

  • 巡覽 content、discovery 與 communication 區域，透過 hover / menu / interaction 找可重用 functionality。
  • 候選工具以「明確使用者意圖、最大覆蓋、最小冗餘」為選擇原則。
  • 典型類型：search / filter / sort、create / edit / delete、comment / message / upvote。
§3.2 p.4
03 · STAGE 2

從 demonstration trace 合成 executor 與 contract

Bbrowser

  • 執行 candidate 並產生 grounded trace X
  • 保留穩定 selector 與 alternative selector
  • 在真實 timing / layout 條件示範功能

Btool

  • 把 trace 分類成 navigation / extraction / interaction / agentic step
  • 推導 enum、optional field、usage example
  • 可行時將 UI chain 升格成 URL operation
§3.2 pp.4–5
03 · VALIDATION

只有通過 end-to-end test 的工具能進 runtime

  1. 以預先整理的 Itest 註冊並測試 tool。
  2. 失敗回傳 selector drift、缺 enum、timeout 或 URL promotion mismatch。
  3. 修 selector / schema / script 後重試；超過固定 budget 就拒絕此 candidate。
  4. 部署後才遇到未知失敗，才叫新 agent 作最後 fallback。
驗證閘門把「看起來像 automation」和「可依賴的 action」分開。
§3.2 p.5; Algorithm 1 pp.15–16
MECHANISM · THE DESIGN CHOICE

Agentic reasoning 是例外路徑，不是 executor 的預設。

短 action script 通常是 URL promotion；較長的 content-management script 多為 deterministic UI interaction。Classifieds 分析中，9 個工具僅 3 個包含 agentic step。

§4.5 p.7
04 · EVALUATION

兩個 benchmark，binary success 而不是 LLM 自評

VisualWebArena

  • 910 個 visually grounded、human-annotated tasks
  • Classifieds 234 · Shopping 466 · Reddit 210

WebArena

  • 812 個 tasks、6 類網站 / multi-site setting
  • GitLab, Map, Shopping, CMS, Reddit, Multi-site
成功以 benchmark evaluator 判定；不是 agent 或 LLM 說「我完成了」就算。
§4.2 p.6
04 · SETUP

對照控制了什麼

  • Planner 使用 GPT-5，browser action executor 使用 GPT-5-mini；每個 task 最多 30 steps、每 15 steps replan。
  • 觀察包含 indexed Set-of-Mark screenshot 與對應 interactive elements；trajectory summaries 以 task intent 做 retrieval。
  • 外部驗證器使用 GPT-5-mini；比較涵蓋 skill induction、MCTS / reflective MCTS、API agent、computer-use agent 與 SGV。
§4.3–4.4 p.6

05 · WHY IT WORKS

WALT 的增益是把錯誤機會從「每一步 UI 推理」移到一次驗證過的工具邊界。

tool / no-tool control 共用 architecture，工具帶來的 30.7% relative gain 與 1.4x efficiency 不能只歸因於更強的 GPT-5。

工具化不是省 token 的包裝；它是對執行可靠性與可審計性的架構重分配。
Fig.3; §4.5 p.7
05 · QUALITATIVE

成功任務：2–5 個 call，先縮小候選空間，再做必要的感知

成功例以 URL search / sort 直達結果集合；失敗例把 global optimum、fine-grained visual predicate 與缺失的 rating tool 疊在一起。
Fig.5; §4.5 pp.8–9
06 · LIMITS

工具邊界不會自動消失

  • Discovery cost：每個網站都要承擔 offline exploration 與 validation 成本。
  • Site volatility：A/B test、CAPTCHA、anti-automation、重設計與稀有參數都會破壞 determinism。
  • Coverage：complex editor、file upload 和未被網站暴露的功能仍可能要 agentic step。
  • External validity：僅在兩個研究 benchmark 評測；enterprise app 的可遷移性尚未驗證。
§5 p.9
06 · ENGINEERING TAKEAWAYS

把 agent capability 做成可維護介面，而不是祈禱 trajectory 記得住

  1. 先找已有功能：優先從 UI / URL / site semantics 萃取 contract。
  2. validation 是 admission control：不通過測試的 tool 不進 runtime。
  3. 保留 fallback，但要可觀察：把 agentic recovery 當例外事件收集。
  4. 把 drift 納入生命週期：selector、schema 與 test input 都需要 online patching 策略。
§3.2 pp.4–5; §5 p.9
APPENDIX · PAPER HIGHLIGHT

核心論述：不是猜技能，而是暴露既有自動化

Rather than hypothesizing ad-hoc skills, WALT exposes robust implementations of automations already designed into websites.

WALT 不猜測臨時技能，而是把網站原本就設計好的自動化能力，變成可呼叫且更穩健的實作。Abstract p.1

這個取向把「網站意圖」和「agent 的低階操作」拆開，才有機會讓後者被測試與維護。

Abstract p.1
APPENDIX · PAPER HIGHLIGHT

部署條件：驗證成功才開放呼叫

Only tools that pass validation within a fixed number of attempts are exposed to the agent at runtime.

只有在固定次數內通過驗證的工具，才會在執行期提供給 agent。§3.2 p.5

這條 gate 很實際：它把「腳本能跑」和「操作值得被 policy 信任」分成兩件事。

§3.2 p.5

WALT 的核心不是讓 agent 多一串 skills

而是把 browser automation 改造成：semantic plan → validated tool → observable fallback。
