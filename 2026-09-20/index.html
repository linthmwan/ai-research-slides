MinerU2.5-Pro

資料工程能不能在不改模型架構的前提下，繼續把 document parsing 往上推？

Bin Wang, Tianyao He, Linke Ouyang, Fan Wu, Zhiyuan Zhao, Tao Chu et al.

TL;DR

固定同一個 1.2B backbone，靠資料覆蓋、跨模型驗證與標註修正，Full score 從 92.98 到 95.69。

重點不是「資料更多」；而是把每個樣本該如何被採樣、信任與修正，連成可控的閉環。

PROBLEM 01

頂尖模型一起跌倒，問題可能不是某一個架構

  • 作者比對不同 architecture 與 parameter scale 的模型，發現它們在同一批 hard samples 上有高度相似的失敗型態。
  • 這讓「再換一個 backbone」不再是唯一假設：共同資料缺口可能才是剩餘瓶頸。
  • 文件解析是 LLM training-data pipeline 與 RAG 的底層基礎；長尾版面或錯標註會沿 pipeline 擴散。
§1 pp.3–4
PROBLEM 02

資料量、資料價值、標註可信度是綁在一起的

Coverage

  • MinerU2.5 原訓練資料 <10M pages。
  • 常見學術論文與單欄報告佔比高。
  • 巢狀 table、密集 formula、非常規 multi-column 是長尾。

Annotation quality

  • 最難樣本最可能提供進步，但自動標註最不可靠。
  • 直接擴量會一起放大 distribution bias 與 annotation noise。
  • 所以 hard sample 需要不同於 easy data 的處理。
§1 p.4
CONTRIBUTIONS

四個元件，組成一個固定架構下的 data-centric 實驗

  1. Data Engine：DDAS + CMCV + Judge-and-Refine，同時管 coverage、informativeness、accuracy。
  2. Progressive training：large-scale pre-training → hard-sample SFT → GRPO alignment。
  3. OmniDocBench v1.6：修 matching bias，另設 Hard subset 與三層 protocol。
  4. Controlled comparison：沿用 MinerU2.5 的 1.2B architecture，將 performance gain 鎖定在 data/training。
§1 p.4 · §4 p.10 · §5 pp.12–14
DATA ENGINE / SAMPLING

DDAS：在 page 與 element 兩層同時平衡 diversity × difficulty

不是平均抽樣：large clusters 下採樣、small clusters 上採樣，Medium/Hard 再上權重。
Fig.3 · §3.1 pp.7–8
DATA ENGINE / CMCV

跨模型一致性，將「難」拆成三種可行動的狀態

TierCross-model patternData action
EasyTarget 與至少一個外部模型一致consensus annotation 可直接使用
Medium兩個外部模型一致；target 顯著不同高價值 capability gap；外部 consensus 當 pseudo-label
Hard三個模型 pairwise 都顯著不一致不直接信任；送 Judge-and-Refine / expert

模型池：MinerU2.5、PaddleOCR-VL、Qwen3-VL-30B；task metrics：text edit distance、table TEDS、formula CDM。

§3.2 p.8
MECHANISM

Medium 不只是「有點難」；它是目標模型缺、別人已會、而且標籤可取得的樣本。

CMCV 的價值是把 annotation budget 從全域平均分配，改為由 cross-model failure pattern 導流。
§3.2 pp.8–9
HARD CASES

Hard samples 不能直接餵進去：錯標註會反過來傷害模型

  • Hard = 所有模型都無法達成可靠 consensus；若直接當訓練標籤，annotation noise 會降低而非提升 performance。
  • 流程先讓 multimodal Judge 定位錯誤與原因，再由 Refiner 針對性修正；殘餘失敗才送 targeted expert annotation。
  • 人工優先順序：Judge 高信心定位、但 Refine 沒修正成功的樣本，因為局部 correction 的產出較高。
§3.3 pp.9–10
JUDGE-AND-REFINE

render-then-verify：把 sequence 裡不顯眼的錯，變成 image 裡顯眼的錯

Naive self-reflection 的盲點

  • 模型由 document image 生成 structured sequence 很擅長。
  • 但只看 sequence 時，難以反推它 render 後是否視覺正確。
  • 因此會有系統性傾向肯定自己的 output。

Render-then-verify 的改變

  • compile LaTeX / render HTML table 成 image。
  • original image + rendered image 作 paired visual input。
  • missing alignment、unclosed tag 等結構錯會被 layout collapse 放大。
§3.3 p.9
CROWN INSIGHT

「讓模型改答案」不是關鍵。
先補上它缺少的 output → visual 檢查路徑，才讓 correction 變得可靠。

這是將 inspection 從 token-space 轉回 document-space 的設計。
§3.3 p.9

STAGE 1

65.5M samples：先把 coverage 與 baseline capability 打厚

Data composition

  • text 21M
  • layout 14M
  • formula 13M
  • table 11.5M
  • image analysis 6M

Sampling principle

  • 以 benchmark metric weights 與 baseline per-task gaps 調整 subtask ratios。
  • 相較 baseline Stage 1：6.9M × 2 epochs → 65.5M × 1 epoch。
  • 擴量同時帶 DDAS correction 與 CMCV filtering，而非 raw scale-only。
§4.1 p.11
STAGE 2

192K expert Hard samples，但不犧牲普通情境的泛化

  • Stage 2 使用 high-quality expert Hard data，並混入 Stage 1 replay 防 catastrophic forgetting。
  • Hard:Replay ratio 隨 subtask 改變：layout 6:1、text 1:50、formula 1:25、table 1:10、image 1:4。
  • 比率反映 hard-sample volume 與既有能力：text hard cases 少，因此 replay 比例特別高。
§4.2 p.11
STAGE 3 / GRPO

把訓練目標接到最終的 structure-level metrics

reward = edit distance / CDM / TEDS / IoU   ·   G = 16 rollouts
  • cross-entropy 對每一 token 分別處理，不能直接反映 edit distance、CDM、TEDS 或 IoU。
  • GRPO 在同一 input 的 candidate group 裡用 relative advantages 更新，不需單獨 reward model。
  • 只保留中等 reward 區間：太高代表已飽和，太低可能太難或 annotation 有誤。
§4.3 pp.11–12
BENCHMARK

v1.6：先修「評分在量什麼」，再比較模型

固定 one-to-one matching 會讓輸出 format / granularity 偏好混進 score。
Fig.4 · §5.1 pp.12–13
MGAM

只調 prediction granularity，找三種候選中分數最好的 matching

  1. Direct: 原始 granularity 下，對 P 與 G 做 bipartite matching。
  2. Split: 依 LaTeX line-break 等 delimiter 拆 prediction，再做 matching。
  3. Partition: 枚舉連續 subsequence 的 ordered partitions、重新 matching；在三個 aggregate score 中選最大。
Cij = 1 - sim(pi, gj)   ·   M* = arg max Sk

WHAT ACTUALLY MOVED THE NEEDLE

最大的單段增益是 Stage 1 的 +1.31。
這份 ablation 支持的不是泛泛的「data is all you need」，而是有篩選、有置信分層、有品質控管的資料系統。

固定 architecture 的設計，使「data coverage + annotation quality」成為一個較乾淨的因果解釋。

LIMITS

v1.6 修了公平性，但還沒有解掉「語意等價」

  • Matching still has a ceiling：HTML vs Markdown table、不同 LaTeX 寫法、text pair vs two-column table 都可能同樣正確。
  • Coverage remains incomplete：finance、legal、medical 等 high-precision verticals 需要 domain-specific benchmarks。
  • Parsing is not understanding：heading hierarchy、figure/table references、cross-page continuity 仍是下一階段的 structured semantics。
§7 pp.17–18
APPENDIX / AUTHOR HIGHLIGHTS

原文裡最值得保留的四句話

“the current performance bottleneck in document parsing stems primarily from shared deficiencies in training data, not from model architecture itself.”

跨架構的系統性失敗，讓作者將主要瓶頸指向共享訓練資料缺陷，而不是模型架構。§1 p.4

“the error-amplification effect of rendering translates subtle, text-domain structural flaws ... into salient visual anomalies or layout collapse.”

rendering 會把文字域中細微的結構錯，放大成明顯視覺異常或版面崩壞。§3.3 p.9

“Stage 1 ... contributes the largest single-stage gain (+1.31).”

Stage 1 的 +1.31 是最大單段增益，支持資料覆蓋與標註品質是主要 performance driver。§6.2 p.15

資料系統，不是資料堆積

MinerU2.5-Pro 的可取之處，在於把 sample selection、label trust、correction budget 與 evaluation protocol 一起做成可驗證的設計。
