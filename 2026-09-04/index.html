MicroMix: Efficient Mixed-Precision Quantization with Microscaling Formats for LLMs

ICLR 2026 paper: threshold-driven MXFP4/6/8 quantization plus Blackwell-aware GEMM kernels for near-FP16 accuracy and real inference speedups.

ICLR 20262026-09-04Compression / Efficiency
Wenyuan Liu, Haoqian Meng, Yilun Luo, Yafei Zhao, Peng Zhang, Xindian Ma · Tianjin University

Source artifacts: arXiv 2508.02343v2 · OpenReview P5OKoZdwlB · local PDF/raw/spec verified.

Abstract p.1; arXiv:2508.02343v2
One-sentence TL;DR

MicroMix treats bit allocation and kernel format as one problem: decide which channels deserve MXFP8, then execute the remaining majority on MXFP4/6 Tensor Cores.

The useful part is not "average 5 bits" by itself; it is the chain: thresholded error budget -> stable channel partition -> fused reorder -> MXFP GEMM.
Abstract p.1; §3.1 p.4-5; §3.2 p.6
Why this paper matters

INT4 wins storage, but can lose the hardware path

  • INT-centric quantization often dequantizes on CUDA Cores before partial sums, because INT8 Tensor Cores accumulate to INT32.
  • Blackwell FP4 Tensor Cores offer up to 4x FP16 throughput and 2x FP8/INT8 throughput, but only if the quantized format matches the hardware path.
  • Fixed mixed precision assigns the same high-precision budget across layers, even though activation distributions differ layer by layer.
  • Open question: what is the threshold where MXFP4/6 error becomes too high and a channel should be promoted?
The paper is really about removing the gap between quantization math and actual kernel throughput.
§1 p.1-2; §2.2 p.3-4
Motivation figure

Layer distributions are not uniform, so fixed channel budgets are brittle

  • Atom-like fixed high-precision counts ignore layer heterogeneity.
  • Larger activation channels need higher precision to reduce quantization error.
  • MicroMix reorders outlier channels and applies layer-wise adaptive precision ratios.
The bit budget has to follow the layer, not the other way around.
Figure 2 and Motivation 1, §2.2 p.3-4
Contributions

What MicroMix adds

  1. MXFP4 / MXFP6 / MXFP8 mixed precision with arbitrary per-layer ratios and BFloat16 outputs.
  2. Quantization thresholds T(4), T(6) that promote elements when low-bit error exceeds the target bound.
  3. Offline channel assignment using calibration-time channel absolute means and layer-specific p4/p6/p8.
  4. Fused reorder-and-quantize + MX GEMM kernels so adaptive precision does not become irregular-memory overhead.
  5. Broad eval across Llama, Qwen, Mixtral, Code, Math, KV cache, and three Blackwell GPUs.

Method · error budget

Promotion rule: low-bit MX error should stay within the INT8 bound

E(X)MXFP{4,6} <= E(X)INT8, for X in G{4,6}
T(n) = 2b x 2n-1 / qmax x E(X)INT8
  • n is the target bit-width; b and qmax are format-specific.
  • Appendix C.2 rewrites the threshold with max(|X|)/254 from the INT8 error bound.
  • A channel that violates the lower-bit error budget is promoted to a higher MXFP format.
Eq.4 and Eq.6 §3.1 p.4; Eq.21 Appendix C.2 p.17
Method · partition

T(4) and T(6) turn outliers into explicit precision groups

G4 = {X | X <= T(4)}; G6 = {X | T(4) < X <= T(6)}; G8 = {X | T(6) < X}
  • G4: normal values, fastest path, majority of channels.
  • G6: middle values that need more dynamic range.
  • G8: outliers that would dominate low-bit error.
  • p4 consistently exceeds 50% in Llama3.1-8B measurements.
  • p4/p6/p8 are layer-specific but stable across sampled datasets and sequence settings.
  • That stability makes offline assignment practical.
Eq.8 and Figure 3 caption, §3.1 p.5
Method · offline calibration

Runtime only applies a precomputed assignment

Mk = channel-wise mean(|Xk|); sigmak = argsort(Mk)
  • For each linear layer k, precompute {p4k, p6k, p8k, sigmak}.
  • Channels are sorted by absolute mean, then sliced into G4/G6/G8 according to the layer ratios.
  • The paper evaluates 32 samples from WikiText2/Pile over batch 8-64 and seq 512-4096.
Eq.9-10 and Figure 3 caption, §3.1 p.5
Kernel co-design

The kernel path is where the average bits become speed

  • MXFP fragments and scale factors are loaded to Shared/Tensor Memory.
  • MMA instructions fuse dequantization and accumulate FP32 partial sums into BFloat16 result matrix.
  • Separate data-type kernels make the precision ratios adjustable without changing the whole pipeline.
§3.2 p.6; Figure 4 p.6
Fusion detail

Adaptive precision would be expensive unless reorder is fused

  • Mixed-precision channel layouts cause irregular memory access if applied naively.
  • Activation reorder-and-quantize is dynamic, so it must be fast.
  • Weights can be permuted and quantized offline as a one-time preprocessing step.
This is the engineering move that makes the threshold algorithm deployable.
§3.2 p.6; Figure 5 p.6

Mechanism crown page

The result works because MicroMix does promotion only where the error budget demands it, then makes that irregular decision look regular to the GPU.

  • Thresholds keep FP4/FP6 groups near the INT8 stable-error region.
  • Offline channel sorting makes layer-specific bit ratios cheap at runtime.
  • Fused reorder-and-quantize prevents adaptive precision from becoming memory-access tax.

Limitations

Strong result, but the deployment envelope is specific

  • Hardware-bound: the main speed claim depends on Blackwell MXFP/FP4 Tensor Core support.
  • Kernel integration: benefits require custom kernels, fused reorder, and framework-level integration; it is not a drop-in weight file.
  • Calibration and preprocessing: each layer needs offline p4/p6/p8 and sigma; weights are permuted/quantized offline.
  • Review data unavailable: OpenReview forum exists, but reviewer JSON was HTTP 403 during ingest, so no reviewer score/concern page is included.
  • Scope: paper tests Llama/Qwen/Mixtral and selected Blackwell GPUs, not every serving stack or multi-node setup.
§3.1-3.2 p.5-6; §4.4 p.9-10; ingest log
Engineering read

What to steal for image / LLM systems work

  1. When a quantization method claims lower bits, ask whether the hardware kernel can consume that exact format directly.
  2. For mixed precision, avoid a fixed global high-bit budget; let an error threshold or per-layer sensitivity decide allocation.
  3. Treat reordering as part of the algorithm, not a bookkeeping step; irregular layouts can erase theoretical wins.
  4. Report average bits together with latency, memory, and accuracy; average bits alone is an incomplete metric.
  5. For new GPUs, revisit old compression assumptions: FP4/MXFP changes the right algorithmic target.
