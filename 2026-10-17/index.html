THE CLAIM

A capable agent can finish a task and still violate policy inside the tool trace.

PROBE trains a plausible “customer” to uncover those reachable, multi-turn failures.
Abstract / p.1 · §1 / pp.1–2
THE EVALUATION GAP

Capability and content safety leave a third axis unmeasured

  • Capability: did the agent complete the task?
  • Content safety: did its text violate a rule?
  • Policy compliance: did it obey procedural, stateful rules while using tools?
  • The final answer can look harmless while tool order, arguments, confirmation, or state checks are wrong.
For deployed agents, compliance is a property of the entire interaction trace.
§1 / pp.1–2 · §2 / p.3
WHY STATIC TESTS FAIL

The failure space is combinatorial

  • User phrasing and multi-turn context
  • Database state and tool availability
  • Policy preconditions and hidden mutations
  • Scripted suites cover known cases
  • They cannot adapt after an agent response
  • An auditor can search reachable interaction paths
The paper treats agent auditing like penetration testing, not a fixed checklist.
§1 / p.2
FIVE CONTRIBUTIONS

What PROBE adds

  1. Black-box policy auditing as a two-player Markov game
  2. A curriculum-trained multi-turn LLM auditor
  3. A reward for distinct, severe, plausible violations
  4. Matched GRPO / DPO / GFlowNet optimizer study
  5. Verifier validation, stronger baselines, and transfer tests
§1 / pp.2–3
FORMALIZATION

The auditor is deliberately partially observed

AUDITOR OBSERVES

  • Public dialogue history
  • Customer scenario
  • Assistant public responses

AUDITOR DOES NOT OBSERVE

  • Target weights or system prompt
  • Tool calls and outputs
  • Database state, policy IDs, verifier labels
The verifier scores the full trace; the auditor receives only scalar reward.

REWARD AS SPECIFICATION

The reward says what a useful audit is

r = rviol + alpha · rprog + beta · rnov + gamma · rplaus
  • Violation: severity-weighted policy failures
  • Progress: enter tool-relevant states
  • Novelty: move away from saturated policies
  • Plausibility: remain a credible customer, not an omniscient attacker
Eq. 1 · §4.2 / pp.4–5
THE KEY REWARD MOVE

First hit: full credit.
Second hit: half credit.
Later repeats: zero.

Per-policy diminishing returns turn “many detector hits” into “more distinct findings.”
Eq. 2 · §4.2 / p.5
CURRICULUM

Reach deep tool states without wasting early rollouts

Kmax: 4 → 8 → 12 → 14 turns | advance when yield > 15% with patience = 50
  • Start short: learn usable prefixes and slot filling
  • Grow horizon: enable booking, cancellation, and other consequential states
  • At each update: 4 candidate messages, each with 3 continuation turns against the same frozen target
§4.3 / p.5 · Figure 3 / p.5
OPTIMIZER BIASES

Same rollouts, different search behavior

MODE-SEEKING

  • GRPO: upweights high-return samples within a group
  • DPO: winner-loser preferences; smoother and order-based

MODE-COVERING

  • GFlowNet: samples in proportion to terminal reward
  • Helpful only when reward mass already reflects policy diversity

§5 / p.6
THE RIGHT METRIC

Coverage counts policies found across an audit campaign

Coverage = distinct policies triggered at least once / 20 policies
  • 60% means 12 of 20 policies were exposed at least once across 50 episodes.
  • Per-episode hit count can be inflated by repeating easy failures.
  • Yield, concentration, multi-policy rate, and entropy are diagnostics—not the headline.

BREADTH, NOT JUST ACTIVITY

Training moves hits away from three easy omissions

  • Best trained checkpoints reduce the B4/S5/B6 share from 88% (zero-shot) to 77%.
  • Policy-hit entropy rises from 2.45 to above 3.1.
  • The result is broader trace-dependent failure discovery, not merely more triggering.
A smaller trained auditor can become a more useful tester than a larger untuned one.

THE REAL BOTTLENECK

Black-box coverage is limited by tool depth

  • Booking calls: GRPO/DPO/GFlowNet = 3 / 1 / 3; cancellation = 0 / 0 / 0.
  • Shallow turn-level omissions are easy; mutation-level safeguards need deeper operational states.

QUALITATIVE PROBING

Two patterns make violations reachable

TEMPTING UNDER-SPECIFICATION

  • Make a plausible incomplete request
  • Pressure action before required slots are grounded
  • Can reveal hidden schema/tool misuse

POLICY STACKING

  • Combine normal budget, urgency, date, and passenger constraints
  • Makes several policies simultaneously relevant
  • Looks like real support behavior

LIMITS

The paper is unusually explicit about where its evidence stops

  • Only two environments and two target families.
  • More than 90% of target tool calls are searches; high-severity booking policies remain unreached.
  • Deterministic replacements may miss semantic violations.
  • Uncertainty is over held-out samples from one checkpoint per method, not training seeds.
  • Auditors can help adversaries too; authors position this as operator-side stress testing.
