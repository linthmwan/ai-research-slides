01 / THE WALL

FlashAttention 改善 IO，沒有移除二次互動

  • 長上下文的主瓶頸仍是 query-key 的全配對，時間隨 N2 成長。
  • 作者的單層 forward/backward 實驗裡，96GB GH200 在約 4M tokens 後已無法完成 FlashAttention-2/3。
  • 要把 context 推到千萬、上億級，核心問題是演算法複雜度，不只是 kernel tuning。
Abstract p.1 · §1 pp.1-2
02 / WHY EXISTING LINEAR ATTENTION IS NOT ENOUGH

既有近似各自留下了缺口

  • Linear Attention: 以正特徵映射重排計算，但實驗常有 accuracy loss。
  • Performer: Random Fourier features；文中指出 runtime 對 embedding dimension d 有二次項。
  • Linformer: 以低秩 surrogate 取代 score matrix，需要選 rank，且不支援 autoregressive task。
  • YOSO: hard LSH 不可微、靠 surrogate gradients，並以 post-hoc l2 normalization 取代標準 attention normalization。
§1 pp.2-3 · §3.1 p.6
03 / CLAIMS

這篇實際上交付了四件事

  1. Kernel: 選擇可 sharpen、又可由 LSH sketch 估計的 angular similarity。
  2. Training: 用 soft bucket assignment 取代 hard hash，保持 end-to-end differentiability。
  3. Theory: 用 beta 和 L 分拆 bias / variance，不只報一個 heuristic。
  4. Scale: 在同一套參數下，測到 GPU 12M、CPU 75M tokens 的單層 training stress test。
§1 p.4 · Abstract p.1

Attention 的充分統計量
不需要 N x N score matrix。

RACE 的關鍵不是把矩陣算得更省，而是根本不建立它。

04 / TARGET KERNEL

先用 sharpened angular kernel 逼近 Softmax 的選擇性

sim(Qi, Kj) = (1 - acos(QiTKj / (||Qi|| ||Kj||)) / pi)P
  • 角度 kernel 對向量 norm 不變；P 越大，近似越尖銳。
  • 作者把它當成 Softmax-like target，而不是宣稱等於 Softmax。
§3.1 pp.5-6 · Fig.3 p.6
05 / FROM MATRIX TO SKETCH

同一個輸出位置：full column vs. bucket summaries

Query 只需讀固定數量的 bucket summary，不需掃過所有 keys。
Fig.1 p.2 · §3.2 p.6
06 / SOFT BUCKETIZATION

把不可微的 hash collision 換成可微的 soft assignment

  • 每個 table 畫 P 個 Gaussian hyperplanes。
  • R = 2P 個 hypercube corners 對應 sign pattern。
  • tanh(Wx) 產生 soft sign；softmax(beta x alignment) 形成 phi(l)(x)。
  • 同角度接近的 Q/K 把較多機率放到相同 corners。
  • phi(Q)Tphi(K) 成為 P-powered angular similarity 的平滑近似。
  • 沒有 hard assignment，梯度可直接穿過 bucketization。
Algorithm 1 p.5 · §3.2 p.7
07 / ALGORITHM

每張 hash table 只留兩個 bucket-level sufficient statistics

A(l) = PhiK(l)T 1;   B(l) = PhiK(l)T V
Num = (1/L) Sum PhiQ(l)B(l);   Den = (1/L) Sum PhiQ(l)A(l);   O_hat = diag(Den)-1Num
  • A 是每個 corner 的 key mass；B 是該 corner 的 value-weighted sum。
  • query 以自己的 phi 向量讀出各 bucket summary，再做 attention-like normalization。
  • L 個獨立 tables 平均，用 ensemble 壓低 sketch variance。
Algorithm 1 p.5 · §3.2 p.7
08 / COMPLEXITY

固定 R、L 時，序列長度只線性進入成本

R = 2^PO(LNRd)
  • 每 table: random projection、corner logits、bucket aggregation。
  • 空間：O(L(NR + Rd))。
O(N²d)all-pairs
  • 文中對照 FlashAttention-2/3 的 time complexity。
  • 實務優勢前提：R、L 都遠小於 N，且維持可接受 accuracy。
§3.2 p.7
09 / CAUSAL MODE

Causal prefix scan 有實作；理論保證尚未跟上

  • 作者以 OpenMP/CUDA custom kernels 在 single streaming pass 內計算 causal prefix operations。
  • 語言模型結果採 causal RACE；但 Theorem 2 只涵蓋 non-causal attention。
  • 這不是小註腳：prefix constraint 與 random-feature construction 的交互仍是 open problem。
工程可用性與理論覆蓋範圍必須分開看。
§1 p.4 · §3.3 p.8
10 / THEORY

作者把 approximation error 拆成可調的兩部分

||O_hat - O||rms = O(P/beta + sqrt(log(N/delta)/L)) ||V||F
  • Bias: P/beta。beta 更高，soft bucketization 更接近 hard collision。
  • Variance: sqrt(log(N/delta)/L)。更多 independent tables 降低 randomness。
  • 假設 target kernel row sums 不會接近零，才能穩定 normalize。
  • 結論針對 P-powered Angular Attention，不是對 exact Softmax 的誤差界。
Theorem 2 · §3.3 p.8
MECHANISM / CROWN PAGE

P 決定「想要多尖」。
beta 決定「soft hash 有多偏」。
L 決定「隨機估計有多穩」。

這三個 knob 對應不同失真來源；不是單純把 hash 數調大。

長度以外，RACE 也避開部分 linear-attention 的 d bottleneck

18 / WHAT TO BELIEVE

最扎實的結論，和不該延伸的結論

SUPPORTED

  • LSH sketch + soft bucketization 能把 target-kernel attention 寫成 bucket summary lookup。
  • 本文對 non-causal Angular Attention 提供 bias/variance accounting。
  • 長 context 下的 stress-test curve 確實揭示 O(N) 與 O(N2) 的分野。

NOT YET SHOWN

  • 沒有 causal version 的完整理論。
  • 沒有 end-to-end multi-layer LLM serving 的 production study。
  • 不等於 exact Softmax，也不代表 P/L/beta 不需 tuning。
§3.3 p.8 · §4 pp.10-11 · §5 p.12
19 / ENGINEERING TAKEAWAYS

若把它當成一條系統設計線索

  1. 先定位 workload：N 要真的跨過 all-pairs regime，asymptotic 才能抵消 sketch constant。
  2. 把 P、beta、L 拆開做 tuning：sharpness、bias、variance 不要混成單一 magic number。
  3. Causal path 要另測：本文實作可用，不代表 non-causal theorem 自動遷移。
  4. 把 sketch 與 sparsity 視為可組合；作者也把這件事留作 future direction。
§1 pp.3-4 · §3.3 p.8
APPENDIX / ORIGINAL HIGHLIGHT

作者如何定義核心轉換

RACE avoids explicitly approximating the N x N attention matrix ... [and] sketches the sufficient statistics needed to compute attention outputs directly in linear time.

RACE 不直接近似 N x N 注意力矩陣；它 sketch 出直接計算注意力輸出所需的充分統計量，因此可以線性時間運作。§3.2 p.7

The bound decomposes into a bias term O(P/beta) and a variance term O(sqrt(log(N/delta)/L)).

誤差界拆成由 P/beta 主導的偏差項，以及由 L 主導的方差項。§3.3 p.8

APPENDIX / CAVEAT

算得更長，不代表所有實務代價都消失

  • RACE 仍儲存 token-level soft features；其 memory expression仍含 N R 項。
  • P 增大時 R=2P，因此 sharpness 有成本，不能把 P 無限推高。
  • 極端數字依賴特定 layer/hardware/config；需要用自己的 model shape 與 batch size 重測。
