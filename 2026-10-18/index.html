CLI-Anything

把 GUI 軟體 lift 成 agent-native、可驗證的 command contract

Yuhao Yang, Tianyu Fan, Chao Huang · University of Hong Kong

CLI-Anything: Towards Agent-Native Computer Use · Abstract p.1 · arXiv:2606.03854
TL;DR

不要教 agent 模仿人類點擊；把軟體既有的 state、backend、artifact 變成可呼叫、可檢查、可重播的 contract。

GUI 保留給人類與 fallback；default control plane 改成 stateful CLI harness。

Abstract p.1 · Conclusion p.26
THE PROBLEM

GUI 是人類的壓縮層，卻常是 agent 的資訊瓶頸

  • Pixels hide state: focus、window、selection 與 project graph 被壓成畫面。
  • Motor noise: click coordinates、hover、timing、resolution 與 modal transitions 不是任務語意。
  • Weak feedback: command success 或畫面看似正常，不等於 export artifact 正確。
  • Missed substrate: 很多應用本來已有 API、native format、renderer 或 headless backend。
Abstract p.1 · §1 p.2 · §2 p.3
INTERFACE BOUNDARY

控制點從 screen mechanics 移到 artifact semantics

Human GUI

  • menus / click targets
  • focus changes / dialog timing
  • moving toolbars / platform drift
  • pixel observation

Agent contract

  • domain verbs + typed arguments
  • explicit project/session state
  • JSON inspection + durable history
  • render, export, verify, replay
核心不是「把 GUI 刪掉」；而是把 GUI 從 truth boundary 降成 human display / fallback。

REPORT CLAIMS

五個可檢查的貢獻

  1. Harness Lift SOP：Locate → Model → Design → Implement → Render → Verify → Publish。
  2. Minimal contract：H = (S, C, I, R, V, D)。
  3. Verification / execution symmetry：builder 與 checker 在同一 artifact boundary 對齊。
  4. Two lift modes：外部 backend adapter，或 in-process runtime bridge。
  5. CLI-Hub distribution：skills、registry、installer 與 preview consumer。

MECHANISM

Harness Lift：從 interface archaeology 到 portable skill

品質門檻不是「command 回傳 0」，而是「使用者實際會打開的 artifact 已被驗證」。
Fig.2 p.5 · §3.1 pp.4–5
HARNESS LIFT SOP

七步驟各自把一段 GUI 隱含知識變成 explicit contract

  1. 01 Locate：trace files、backend calls、rendered output。
  2. 02 Model：命名 domain nouns、operations、constraints。
  3. 03 Design：command grammar、JSON replies、recoverable errors。
  4. 04 Implement：project state、session replay、undo / redo。
  1. 05 Render：call real backend、export artifacts、build previews。
  2. 06 Verify：unit / E2E、file + pixel probes。
  3. 07 Publish：SKILL.md、registry metadata、install path。
Fig.2 p.5 · §3.1 pp.4–5
MINIMAL CONTRACT

H = (S, C, I, R, V, D) 是一個對 real backend 的完整操作面

H = (S, C, I, R, V, D)
  • S / State：project、session、undo、preview artifacts。
  • C / Commands：domain mutations 與 probes。
  • I / Inspection：JSON status、list、info、history。
  • R / Render：delegate to real software。
  • V / Verify：E2E、format、pixel/media assertions。
  • D / Discovery：SKILL.md、registry、installer、entry point。
§3.2 p.6
CONTRACT INVARIANTS

跨軟體不統一 noun，統一的是六個 operational invariant

  1. Explicit state：workspace 必須可命名、儲存與 inspect。
  2. Typed actions：commands 映射到 domain operations，並回 actionable errors。
  3. Cheap inspection：下一步之前能問清楚 changed state。
  4. Backend truth：render/export 走真實軟體或 native backend。
  5. Programmatic verification：檢查使用者會開啟的 artifact。
  6. Discoverability：agent 可找到、安裝、讀取並 invoke interface。
§3.2 p.6
CROWN INSIGHT

如果 checker 能在某個 file / package boundary 證明 truth，
builder 就該在同一 boundary 建構與 export。

Verification is not the last step; it reveals the right execution boundary.

§3.3 p.7 · Fig.3 p.7
SYMMETRY IN PRACTICE

同一 artifact boundary 把 build、inspect、diagnose、revise 串成 loop

Execution builder

  • commands choose state
  • backend writes native files
  • session records lineage
  • export target artifact

Verification checker

  • parse package / structure
  • count semantic objects
  • test pixels, media, metadata
  • write diagnosis, revise, re-export
Exit code 只是 supporting evidence；structured artifact 才是 shared surface。
§3.3 pp.7–8 · Fig.3 p.7
STATEFUL CLI

Agent workspace 不是一串 shell call，而是可恢復的 state graph

  • Persistent JSON project 讓 agent inspect、diff 與 recover。
  • Session files + history 保存 project path、modified state 與 replay context。
  • Undo / redo + dry run 讓 exploration 可逆，先測 plan 再 mutation。
  • Locks + deterministic JSON 降低 concurrent write corruption，讓差異可讀。
Human GUI 的 continuity 來自 windows / focus / visual memory；agent 需要檔案、history 與 explicit state。
§3.4 p.8
PREVIEW PROTOCOL

把 visual feedback 變成 backend-grounded 的 display bundle

Producer harness

  • real backend render
  • recipe + source fingerprint
  • publish preview bundle
  • owns truth and mutation

Consumer / CLI-Hub

  • inspect / html / watch / open
  • reads without mutating
  • generic across CAD, video, 3D, diagrams
  • human + agent share same evidence

Bundle: manifest.json, summary.json, artifacts/; live workflows add session.json and trajectory.json.

§3.5 p.9 · Fig.4 p.9
DISCOVERY IS RUNTIME

能被呼叫的 harness，也必須能在 task time 被找到與安裝

  • SKILL.md 提供 command groups、examples、JSON usage、prerequisites 與 constraints。
  • Registry metadata 讓 agent 依 capability / category 找候選 interface。
  • Mixed installation 支援 pip、npm、uv、bundled/system、command-based installers。
  • Future target：structured capability search、install plan、backend diagnostics、direct skill fetch。

CASE STUDY A

Blender：在既有 backend scripting boundary 外側加一層 agent contract

  • Native Blender already exposes bpy / RNA / operators / render engines.
  • Harness keeps .blend-cli.json as inspectable working state.
  • Lowering pass transforms JSON scene contract into executable bpy.
  • Headless Blender remains responsible for scene semantics and final rendering.

CASE STUDY B

Slay the Spire II：沒有成熟 backend 時，bridge 必須住在 state 所在的 runtime 內

  • In-process C# bridge reads live Godot / game objects and schedules work on the frame-owned main thread.
  • External Python CLI stays deliberately small: typed HTTP client, JSON normalizer, Click + REPL.
  • Semantic lift turns screen/overlay detail into stable decision states and verbs such as play-card / choose-map / proceed.
  • Authority stays native：game still decides legal targets, combat resolution, transitions, rewards, and save state.

WHY IT MAY WORK

Semantic verbs collapse many accidental pixel traces into one stable, compositional action space.

The bridge absorbs cursor paths, timing, frame ownership, and UI specifics; the agent plans over state + legal actions.

§4.2 pp.16, 18–20
FAILURE MODES

系統化的 failure analysis 比「包一層 CLI」更重要

  1. Backend exits but artifact is useless → validate rendered outputs, magic bytes, structure, pixels/media.
  2. Project mutation does not survive export → document project-only features or add real render mappings.
  3. Stateless commands lose context → session state, autosave, status probes, undo/redo.
  4. Decorative screenshot loses truth → bundle protocol tied to real project state and backend artifacts.
  5. Tool is unfindable / un-installable → registry, install strategies, skills, clear backend errors.
§6 p.25
LIMITS

不是每個 application 都能被乾淨地 lift

  • Opaque binaries and hidden state may still require accessibility APIs or GUI automation.
  • Creative decisions can require rich visual judgment beyond a typed command surface.
  • Preview integrations are early and may not cover meaningful visual state completely.
  • Web, mobile, and desktop GUI-agent methods remain relevant when pixels / browser-native interaction are the only available truth boundary.
適用條件很清楚：能找到或插入 inspectable state、semantic action、native render/export、以及 executable verification。
§3.2 p.6 · §7 p.25
ENGINEERING TAKEAWAYS

給 agent 工程師的實作優先序

  1. 先找 artifact / backend truth boundary，再談 tool schema 或 agent prompting。
  2. 把 inspection 做到便宜且 machine-readable；每一步都能問「現在狀態是什麼」。
  3. 把 verification 接到 user-visible artifact，而不是 process return code。
  4. 把 session、undo、preview、trajectory 當成 interface 一部分，不是 debug 附件。
  5. 把 discovery / install / skill metadata 當 runtime system，而不是 README 裝飾。
§3 pp.4–10 · §6–7 pp.25–26
APPENDIX / PRIMARY CLAIM

If the artifact can be inspected programmatically, then in many cases it can also be constructed programmatically.

如果成品可以被程式檢查，那麼很多情況下也能透過程式建構。

This is the report’s strongest design thesis: validation exposes the right construction boundary.
