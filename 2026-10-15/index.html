THE ONE-LINE THESIS

不要把所有非關鍵注意力都丟掉。
把少量高秩部分算準，把大量低秩部分交給可學的線性補償。

SLA reports 95% attention sparsity while retaining its reported video quality.
Abstract p.1 · §3.2 p.3–4
01 · BOTTLENECK

影片 DiT 的問題不是 attention 很貴而已

  • Video Diffusion Transformer 的序列長度通常是 10K–100K tokens。
  • Attention 是 Transformer 中唯一隨序列長度呈二次成長的主操作。
  • 因此只把 kernel 做快不夠；要改變被計算的 attention 結構。
目標是減少 attention 計算，同時不把影片品質換掉。
§1 p.1
02 · WHY EXISTING ROUTES STALL

Sparse-only 與 linear-only 各自卡住一半問題

Sparse attention

  • 能保留精確高值，但在 <50K token 時通常只到 40–60% sparsity。
  • 再往上切，邊際權重的誤差迅速累積。

Linear attention

  • 理論上是 O(N) 路線，但直接套到影片 diffusion 會嚴重傷害品質。
  • 它受可表示的低秩結構限制。
§1 p.1
03 · EMPIRICAL CLUE

權重分佈指出「什麼可以跳過」還不夠

  • 約 45% 權重低於 1/(100N)：跳過後相對 L1 error <3%。
  • 只保留最大 8.1%（92% sparsity）：error 約 33%。

MECHANISM

Sparsity is for the high-rank few.
Low-rank / linear structure is for the many.

P = P x M + P x (1 - M)
The paper changes the target from “approximate all attention” to “route different attention structure to different computation.”
Eq.1 · §3.2 p.4
05 · SLA ROUTING

一個 compressed mask，三種運算路徑

Mask construction

  • Mean-pool Q and K, then form a compressed attention map Pc.
  • Per row: top kh% -> critical; bottom kl% -> negligible; the rest -> marginal.

Compute assignment

  • Critical: exact sparse FlashAttention
  • Marginal: linear attention
  • Negligible: skip
Pc = softmax(pool(Q) pool(K)T / sqrt(d))
Eq.2–3 · §4 p.4
06 · CRITICAL PATH

Critical blocks stay exact

  • Compressed mask selects the high-value blocks; only those run score, OnlineSoftmax, and value accumulation.
  • This preserves the rare high-rank content that linear attention cannot faithfully represent.
  • The implementation is blockwise, so it is compatible with sparse FlashAttention-style execution.
Sij = QiKjT / sqrt(d)   ;   Os = sparse exact output
§4.1 · Eq.4 p.4
07 · MARGINAL PATH

Marginal blocks use aggregated linear statistics

  • For blocks marked marginal, SLA accumulates Hi and Zi from phi(K)TV and row sums.
  • The operation avoids materializing an N x N matrix.
  • The paper precomputes per-K/V-block statistics so routing only requires additions.
Ol,i = phi(Qi) Hi / (phi(Qi) Zi)
§4.2 · Eq.5 p.5
08 · THE IMPORTANT CAVEAT

Linear attention is not claimed to approximate the marginal output directly

What SLA does

  • Combines exact sparse output with a projected linear branch.
  • Fine-tunes the model so it adapts to the altered computation.

What SLA does not claim

  • Linear-only attention is not sufficient for lossless video generation.
  • Simply adding independent sparse and linear outputs is not the same as SLA.
O = Os + Proj(Ol)
The learned projection manages the softmax-versus-linear distribution mismatch.
Eq.6 · §4.2 p.5
09 · TRAINING

Fine-tuning is part of the method, not a footnote

  • Replace attention with SLA and fine-tune on data consistent with pretraining.
  • Main video setup: 2,000 steps, batch 64, using 20,000 five-second 480p videos.
  • The authors describe this as <0.1% of typical pretraining cost.
SLA buys its hybrid approximation with a small adaptation budget; it is not training-free.
§5 p.5 · §6.1 p.7 · §6.3 p.8
10 · GPU KERNEL

The algorithm and the kernel are co-designed

Forward / backward

  • Sparse and linear components are fused into GPU kernels.
  • Backward computes gradients for both components with precomputed linear derivatives.

High-sparsity engineering

  • Lookup table reduces mask-scanning traffic above 90% sparsity.
  • Pre-aggregation changes many additions into fewer subtractions.
§5.1–5.2 p.5–7 · Appendix A.3 p.15
11 · EXPERIMENT DESIGN

Main benchmark: Wan2.1-1.3B video generation

  • Baselines include VSA, VMoBa, training-free Sparge-F, trainable Sparge-T, Linear Only, Sparse Only, and L+S.
  • Quality: VBench IQ / OC / AQ / SC, Vision Reward, VA, VT.
  • Cost: FLOPs, attention kernel FLOPS, and end-to-end generation latency.
  • Main routing hyperparameters: kh = 5%, kl = 10%, bq = bkv = 64.

18 · WHAT THE PAPER ACTUALLY ESTABLISHES

Strong evidence, with bounded scope

Supported by the paper

  • A hybrid routed mechanism outperforms listed sparse / linear baselines on Wan2.1-1.3B.
  • A fused implementation has large measured kernel gains on RTX5090.
  • A small fine-tune can recover quality under this routing.

Not established here

  • A training-free replacement for video attention.
  • Exact reproducibility of the private video fine-tuning data.
  • Uniform benefits across every DiT, GPU, sparsity pattern, and production pipeline.
§5–6 p.5–9 · Appendix A.2–A.3 p.15
19 · LIMITS

Four practical boundaries

  • The main video data are private (Pexels and Common Crawl collection), so exact reproduction is constrained.
  • SLA requires a fine-tuning pass; it is not a drop-in inference-only method.
  • The kernel needs sparsity-regime-specific optimizations, which complicates implementation.
  • Primary video evidence centers on Wan2.1-1.3B; image results are supplementary.
§5 p.5 · §6.1 p.7 · Appendix A.2–A.3 p.15
20 · ENGINEERING TAKEAWAY

First discover the structure your accelerator should preserve

  • Start from error / rank anatomy, not only a target FLOPs percentage.
  • Route the irreplaceable component to exact computation; approximate only what has the right structure.
  • Treat kernel design, training adaptation, and model approximation as one system.
  • Report both kernel and end-to-end speed: their difference says where the next bottleneck is.
The useful abstraction is heterogeneous attention computation, not a single universal “efficient attention” trick.
