MVP: A Motion-Predictive Speculative Vision Pipeline with Non-Blocking Drift Correction

把 continuous vision 的 speculative execution 從 pixel domain 移到 ISP motion-vector domain。

Raul Taranco · Antonio Gonzalez · Universitat Politècnica de Catalunya
MICRO 2026 · AcceptedarXiv:2609.27706v12026-09-24
Source: MVP paper · cover / §III-A p.4 · selected for Thursday compute-acceleration rotation
TL;DR

MVP turns motion extrapolation into the default response path, then moves full inference to a background drift-correction path.

-66.8% P99 tail latency-46% energysmall accuracy cost
The win is not another heavier predictor: it is changing which state gets speculated.
Abstract p.1; §I pp.1–2
THE BOTTLENECK

A pipelined SoC still serializes each individual frame

  • Per-frame sensing → ISP → neural backend handoff dominates end-to-end response time.
  • Safety / XR workloads are latency sensitive: the paper cites <100 ms for AD and <50 ms for XR.
  • Bounded “process-latest, drop-oldest” queues prevent runaway latency, but in overload they sacrifice temporal resolution.
Backend throughput alone does not solve a critical-path dependency.
§I p.1; §II-B p.3
WHY PRIOR WORK LEAVES A GAP

Two useful ideas fail for opposite reasons

MOTION EXTRAPOLATION (CME)

  • Skips some full inferences by propagating old detections with ISP motion vectors.
  • Key frames still pay full backend latency.
  • E-frames may wait for the preceding I-frame; overload can still drop frames.

PIXEL-DOMAIN SPECULATION (PVF / PDSPEC)

  • Predicts full-resolution future frames and runs complete speculative inference.
  • Needs parallel compute; failures require reprocessing.
  • Turning frontend off to save energy creates sensor blind spots.
§II-C pp.3–4
PAPER CONTRIBUTION

Four tightly coupled changes

  1. MVP-SCH: immediate extrapolation for every frame; full inference becomes asynchronous drift correction.
  2. MVP-SPE: speculate one future motion field, validate it at MV arrival, and locally re-extrapolate on mismatch.
  3. ISP extension: confidence-aware MV denoiser plus tile-wise AR(2) predictor.
  4. Optional frontend scaling: use predicted motion as a capture-rate control signal.
§I pp.1–2; §III-A pp.4–5
SYSTEM VIEW

The extra hardware is attached to an existing motion stream

MVP does not add an NPU for prediction; it reuses motion estimation already inside modern ISPs.
Fig. 3; §III-A p.4
MVP-SCH

Drift correction is no longer a blocking dependency

  • DCFD controls the number of frames between full drift-correction frames.
  • MED bounds how far outputs may extrapolate from the last correction.
  • Adaptive DCFD increases the interval when observed error is low and shrinks it when error rises.
§III-B pp.5–6; Fig. 4 p.5
CONTROL KNOB

Correction cadence makes the accuracy–efficiency trade explicit

DCFD = 0 → correct every frame → no drift, no backend saving
higher DCFD → fewer backend executions → more accumulated extrapolation error
  • At short horizons (DCFD ≤ 2), both MVP-SCH and MVP-SPE stay below 1% mAP drop.
  • At DCFD=4, mAP drop is 2.9% / 3.6%; at DCFD=8 it grows to about 10% / 13%.
  • The adaptive operating point limits the observed loss to 1.3% / 1.6% with maximum DCFD=4.
§III-B p.5; §VI-A p.10; Fig. 9 p.10
MVP-SPE

Speculate a cheap state one frame ahead, not an expensive image

A validation miss triggers local re-extrapolation from measured motion vectors — not neural-network re-inference.
§III-C pp.6–7; Fig. 5 p.6
THE SAFETY PROPERTY

Nothing reaches a downstream task before the arriving frame’s motion vectors validate the prediction.

If it fails, MVP discards only the motion update, recalculates from measured MVs, and re-issues the task. No image-generation output, no NPU rollback.

This turns “misprediction” from a full backend replay into a bounded metadata repair.
§III-C pp.6–7
OPTIONAL FRONTEND SCALING

Predicted motion can reduce sensing energy before capture

Ptrigger = min(1, Mpred / Tblink)
  • Always capture one frame; conditionally trigger the next when predicted motion is low.
  • Tblink=2 px / 4 px saves 5.4% / 13.8% frontend energy while meeting the 1.5 mAP target.
  • Aggressive 8 px reaches roughly 50% saving but costs 6.2% mAP — intentionally not a safety-default mode.
§III-D p.7; §VI-E p.12
HARDWARE PLACEMENT

Two streaming blocks live alongside the ISP pipeline

The design is an ISP augmentation, not a second vision accelerator.
§IV p.7; Fig. 6 p.7
MV DENOISER

Filter uncertain block motion before using it as a control signal

MVfiltered(x,y) = sum[c × MV] / sum[c]
MVtemporal = alpha × MVfiltered + (1-alpha) × MVprev
  • A confidence-weighted 3×3 spatial smoother uses SAD-derived match confidence.
  • A confidence-aware EMA fuses the current and previous field.
  • At 1080p, the filtered-MV buffer is about 16 KB.
§IV-A pp.7–8; Eq.1–5 p.8; Fig. 7 p.8
MOTION PREDICTOR

Tile-local AR(2) buys predictability without an ML model

MV_hat(t+1) = a1 × MV(t) + a2 × MV(t-1)
  • Independent coefficients per tile capture local horizontal / vertical dynamics.
  • LMS updates coefficients online from measured prediction error.
  • A bounded velocity-form implementation means a bad learned coefficient only loses speedup; validation protects correctness.
§IV-B pp.8–9; Eq.6–7 p.8; Fig. 8 p.8
EVALUATION

A single-NPU mobile SoC is the deliberate stress test

  • Object detection: YOLOv8 on KITTI, upsampled from 10 Hz to 30 FPS; mAP@0.5 is scored on original labelled frames.
  • Tracking: ByteTrack on KITTI / MOT17 (HOTA); detector generality: RT-DETR.
  • gem5 + DRAMsim3 + ScaleSimv2 model an ARM Cortex-A72 and a 24×24 MAC, 1 GHz NPU.
  • Balanced: YOLOv8s, 28.6B FLOPs. Overload: YOLOv8m, 78.9B FLOPs; baseline sustains 14.7 FPS.
§V p.9
ACCURACY

Adaptive correction stays near the paper’s 1.5 mAP target

The important result is not zero error: it is a controllable operating point before long-horizon drift compounds.
Fig. 9; §VI-A p.10
BALANCED REGIME

Motion-domain speculation improves the latency–energy frontier

  • MVP-SPE-A adds around 22% extra tail-latency reduction over MVP-SCH-A by triggering downstream work one frame ahead.
  • The oracle leaves another 8.78% tail-latency headroom; PDSPEC diverges after 4–5 frames and adds around 10% energy through reprocessing.
Fig. 10 p.10; §VI-B pp.10–11
OVERLOAD REGIME

One backend is exactly where pixel speculation stops helping

  • With one NPU, PDSPEC has no idle capacity and falls back to baseline: 14.7 FPS.
  • CME reaches about 23 FPS, but periodically blocks on full frames.
  • MVP keeps extrapolation as the default and, per the paper, delivers twice the baseline outputs at that cost.
Fig. 11 p.11; §VI-D pp.11–12

MECHANISM · THE CROWN PAGE

MVP wins because drift correction becomes asynchronous and a failed speculation becomes a local motion repair, not a full backend replay.

That is why it can improve tail latency even with a single NPU: the critical path is no longer waiting for a full inference to unblock the next useful output.

Speculate the smallest state that can still advance the application.
§III-B/C pp.5–7; §VI-C p.11
LIMITS

What motion extrapolation cannot invent

  • A newly appearing object waits for the next DC frame; at DCFD=4 and 30 FPS, the paper estimates a worst-case onset around 235 ms.
  • Abrupt motion concentrates the observed 8–12% prediction failures; long DCFD horizons compound drift.
  • The frontend-scaling feature is conditional on application tolerance, not a universal safety setting.
  • Evidence is system simulation plus RTL validation, rather than end-to-end commercial-silicon measurements.
§VI-C p.11; §VI-A p.10; §III-D p.7; §V p.9
APPENDIX · AUTHOR WORDING

The two sentences that define the contract

“Each frame is served immediately via extrapolation, while high-precision frame processing is performed asynchronously on selected Drift-Control (DC) frames to periodically correct prediction drift.”

每個 frame 先立即以 extrapolation 服務；高精度處理只在選定 DC frames 異步執行，以週期性修正 drift。§III-A p.4

“If the check fails, MVP discards only this lightweight motion update, never a neural-network inference.”
